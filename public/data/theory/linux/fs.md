Файловая система в Linux — это не только каталоги и файлы, но и inode, ссылки, точки монтирования и модель прав. На собеседовании любят практические загадки: «диск заполнен, а `du` показывает половину», «места полно, но `No space left on device`», «почему можно удалить чужой файл». Все они решаются пониманием того, как устроены inode и права на каталоги.

## Inode, имена и ссылки

**Inode** хранит метаданные файла: тип, права, владельца и группу, размер, временные метки (`mtime`, `ctime`, `atime`), счётчик ссылок и расположение данных на диске. **Имени в inode нет** — имя хранится в записи каталога, которая связывает его с номером inode.

```bash
ls -li file.txt       # номер inode в первом столбце
stat file.txt         # все метаданные
df -i                 # использование inode
```

| | Жёсткая ссылка (`ln`) | Символическая ссылка (`ln -s`) |
|---|---|---|
| Что это | Ещё одно имя того же inode | Отдельный файл с путём к цели |
| Другая ФС | Нельзя | Можно |
| На каталог | Нельзя | Можно |
| Удаление оригинала | Данные живут, пока есть другие имена | Ссылка становится «битой» |

Данные удаляются, когда счётчик ссылок равен 0 **и** файл никем не открыт. У каталога счётчик ссылок равен 2 (имя в родителе и `.`) плюс по одной ссылке `..` от каждого подкаталога: `drwxr-xr-x 5` означает три подкаталога (на ext4/XFS).

## Монтирование, ext4 и XFS

Все ФС подключаются в единое дерево через `mount`, а постоянные точки описываются в `/etc/fstab`.

```bash
mount /dev/sdb1 /data
mount -o remount,ro /data
mount --bind /src /dst
findmnt /data
# /etc/fstab
UUID=...  /data  xfs  defaults,noatime,nofail  0 0
```

Для `/tmp` рекомендуют опции `noexec,nosuid,nodev`. `nofail` не даёт системе зависнуть при загрузке, если диск отсутствует.

| | ext4 | XFS |
|---|---|---|
| Увеличение | Онлайн (`resize2fs`) | Онлайн (`xfs_growfs`) |
| Уменьшение | Только отмонтированной (`e2fsck -f`, `resize2fs`) | Невозможно |
| Inode | Фиксируются при создании | Выделяются динамически |
| По умолчанию | Debian, Ubuntu | RHEL, Rocky, Alma |

В ext4 5 % блоков зарезервировано для root (`tune2fs -m`).

## df и du: почему они расходятся

`df` спрашивает у ФС, сколько блоков занято, а `du` обходит дерево каталогов и суммирует размеры найденных файлов. Классическая причина расхождения — **удалённый, но открытый файл**: имени нет (du его не видит), а inode и данные живут, пока процесс держит дескриптор.

```bash
lsof +L1                         # открытые файлы со счётчиком ссылок 0
ls -l /proc/1234/fd | grep deleted
: > /proc/1234/fd/7              # усечь файл без перезапуска процесса
```

Другие причины: данные под точкой монтирования, зарезервированные блоки, разреженные файлы. Если запись падает с `No space left on device` при свободных блоках — проверьте `df -i`: могли закончиться inode.

## Права доступа и umask

Права задаются для владельца, группы и остальных: `r=4`, `w=2`, `x=1`. `chmod 750` = `rwxr-x---`.

| Право | Для файла | Для каталога |
|---|---|---|
| `r` | Читать содержимое | Видеть список имён |
| `w` | Изменять содержимое | Создавать, удалять, переименовывать записи |
| `x` | Запускать | Входить (`cd`) и обращаться к файлам по имени |

Удаление файла — изменение каталога, поэтому нужны `w` и `x` на **каталог**, а права самого файла не важны. С `r` без `x` можно увидеть имена, но не открыть файлы.

**umask** снимает биты из базовых прав 666 (файлы) и 777 (каталоги):

```bash
umask 022   # файлы 644, каталоги 755
umask 027   # файлы 640, каталоги 750
umask 077   # файлы 600, каталоги 700
```

## Специальные биты, ACL и атрибуты

| Бит | Число | На файле | На каталоге |
|---|---|---|---|
| setuid | 4000 | Запуск с правами владельца (`/usr/bin/passwd`) | — |
| setgid | 2000 | Запуск с правами группы | Новые файлы наследуют группу каталога |
| sticky | 1000 | — | Удалять файлы может только их владелец (`/tmp`) |

В `ls -l` это `s` вместо `x` у владельца или группы и `t` у остальных. Поиск setuid-файлов для аудита: `find / -perm -4000 -type f 2>/dev/null`.

**ACL** добавляют права для конкретных пользователей и групп:

```bash
setfacl -m u:bob:rw report.csv
getfacl report.csv
ls -l report.csv   # -rw-rw----+  (плюс означает ACL)
```

**Атрибуты** ext4/XFS проверяются раньше прав: `chattr +i` — файл неизменяем даже для root, `chattr +a` — только дозапись; посмотреть атрибуты — `lsattr`.

## find

```bash
find /var/log -type f -name '*.log' -mtime +7 -delete
find / -xdev -type f -size +100M -exec ls -lh {} +
find . -user alice -perm -o=w
find . -name '*.tmp' -print0 | xargs -0 rm -f
```

`-mtime +7` — старше 7 суток, `-7` — моложе. `-xdev` не выходит за пределы текущей ФС. Шаблоны берут в кавычки, чтобы их не раскрыл shell.

## Частые вопросы на собеседовании

- Что хранит inode? → Метаданные и адреса данных, но не имя.
- Hard link vs symlink? → Второе имя inode против файла с путём; hard link не работает между ФС.
- `df` показывает 95 %, `du` — 40 %. Почему? → Удалённые открытые файлы, смотреть `lsof +L1`.
- Места много, но `No space left`? → Закончились inode, `df -i`.
- Зачем sticky bit на `/tmp`? → Чтобы пользователи не удаляли чужие файлы.
- Что даёт umask 027? → Файлы 640, каталоги 750.

## Шпаргалка

- `ls -li`, `stat`, `df -h`, `df -i`, `du -xh --max-depth=1 | sort -h`
- `lsof +L1`, `: > /proc/PID/fd/N`
- `chmod 750`, `chmod g+s dir`, `chmod +t dir`, `chown user:group`
- umask: файлы 666 − маска, каталоги 777 − маска (побитово)
- `setfacl -m u:bob:rw`, `getfacl`, `chattr +i`/`+a`, `lsattr`
- `mount -o remount,ro`, `findmnt`, `/etc/fstab` с `nofail`
- ext4 уменьшается офлайн, XFS — никогда
