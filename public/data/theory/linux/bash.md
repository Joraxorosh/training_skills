Bash остаётся основным языком автоматизации на серверах: скрипты деплоя, entrypoint контейнеров, cron-задачи, шаги CI. На собеседовании дают короткие фрагменты и спрашивают, что они выведут. Большинство ловушек связано с кавычками и разбиением на слова, subshell, порядком перенаправлений и неочевидным поведением `set -e`.

## Переменные, кавычки и аргументы

```bash
name="world"          # без пробелов вокруг =
echo "Hello, $name"   # Hello, world
echo 'Hello, $name'   # Hello, $name — одинарные кавычки ничего не раскрывают
files=$(ls /etc | wc -l)
```

Без кавычек значение переменной разбивается по `IFS` и раскрывается как glob. Правило: **всегда пишите `"$var"`**, если явно не нужно иное.

| Переменная | Значение |
|---|---|
| `$0` | Имя скрипта |
| `$1`…`$9`, `${10}` | Позиционные аргументы |
| `$#` | Число аргументов |
| `"$@"` | Все аргументы, каждый отдельным словом |
| `"$*"` | Все аргументы одной строкой через первый символ IFS |
| `$?` | Код возврата последней команды |
| `$$` / `$!` | PID оболочки / последнего фонового процесса |

```bash
set -- "a b" c
for x in "$@"; do printf '[%s]' "$x"; done   # [a b][c]
for x in "$*"; do printf '[%s]' "$x"; done   # [a b c]
```

Для проброса аргументов в другую команду почти всегда нужен `"$@"`.

## Коды возврата и строгий режим

0 — успех, всё остальное — ошибка. 126 — нет права на запуск, 127 — команда не найдена, 128+N — убит сигналом N.

```bash
cmd1 && cmd2      # cmd2, если cmd1 успешна
cmd1 || cmd2      # cmd2, если cmd1 упала
cmd1 && cmd2 || cmd3   # cmd3 выполнится и при падении cmd2 — это не if/else
```

Строгий режим в начале скрипта:

```bash
set -euo pipefail
```

- `-e` — выйти при ненулевом коде команды;
- `-u` — обращение к неустановленной переменной считается ошибкой;
- `-o pipefail` — код конвейера равен коду последней упавшей команды, а не просто последней (коды всех частей — в `PIPESTATUS`).

> Ловушки `set -e`: он не срабатывает в условиях `if`/`while`, в левой части `&&`/`||` и во всём теле функции, вызванной как `f || echo fail`. А `((x++))` при `x=0` возвращает 1 и завершает скрипт. Безопаснее писать `((++x))` или `x=$((x+1))`.

## Условия, циклы и функции

`[[ ]]` — ключевое слово bash: внутри нет разбиения на слова, есть шаблоны и регулярки. `[ ]` — команда `test` из POSIX.

```bash
if [[ $file == *.log && -s $file ]]; then echo "непустой лог"; fi
if [[ $ver =~ ^([0-9]+)\.([0-9]+) ]]; then echo "${BASH_REMATCH[1]}"; fi
[ -f "$cfg" ] || { echo "нет конфига" >&2; exit 1; }

for f in /var/log/*.log; do gzip "$f"; done
for i in {1..5}; do echo "$i"; done
while read -r line; do echo "$line"; done < input.txt
```

Функция возвращает только код 0–255 через `return`, а данные — через stdout:

```bash
get_version() {
  local v              # local — переменная видна только в функции
  v=$(cat VERSION)
  echo "$v"
}
ver=$(get_version)
```

## Перенаправления, here-doc и subshell

Перенаправления применяются **слева направо**:

```bash
cmd > out.log 2>&1     # stdout и stderr в файл
cmd 2>&1 > out.log     # stderr в терминал, stdout в файл
cmd &> out.log         # то же, что первый вариант (bash)
cmd >> out.log         # дописать
cmd 2>/dev/null
```

Here-doc передаёт многострочный текст на stdin. С кавычками вокруг разделителя ничего не раскрывается:

```bash
cat <<EOF
Home: $HOME
EOF
cat <<'EOF'
Home: $HOME
EOF
```

Во втором случае строка `Home: $HOME` выведется буквально.

`( ... )` запускает **subshell**: изменения переменных и `cd` в нём не видны снаружи. `{ ...; }` группирует команды в текущей оболочке. Каждая часть конвейера тоже выполняется в subshell:

```bash
count=0
printf 'a\nb\n' | while read -r l; do count=$((count+1)); done
echo "$count"          # 0
while read -r l; do count=$((count+1)); done < <(printf 'a\nb\n')
echo "$count"          # 2
```

## Раскрытие параметров

| Выражение | Результат |
|---|---|
| `${v:-def}` | `def`, если `v` пуста или не задана (v не меняется) |
| `${v:=def}` | То же, но ещё и присвоить |
| `${v:?msg}` | Ошибка с `msg`, если пусто |
| `${#v}` | Длина строки |
| `${f%.*}` / `${f%%.*}` | Удалить кратчайший / длиннейший суффикс |
| `${f#*.}` / `${f##*.}` | Удалить кратчайший / длиннейший префикс |
| `${v//a/b}` | Заменить все `a` на `b` |

```bash
f=archive.tar.gz
echo ${f%.*} ${f%%.*} ${f#*.} ${f##*.}   # archive.tar archive tar.gz gz
p=/usr/local/bin/tool
echo ${p##*/} ${p%/*}                     # tool /usr/local/bin
```

## grep, sed, awk и xargs

```bash
grep -rn "ERROR" /var/log/app/        # рекурсивно с номерами строк
grep -v '^#' config | grep -c .       # число непустых строк без комментариев
sed -i 's/foo/bar/g' file             # замена на месте (GNU sed)
sed -n '10,20p' file                  # вывести строки 10–20
awk '{s += $2} END {print s}' data    # сумма второго столбца
awk -F: '$3 >= 1000 {print $1}' /etc/passwd
find . -name '*.log' -print0 | xargs -0 rm -f
```

`-print0` и `xargs -0` разделяют имена нулевым байтом, поэтому файлы с пробелами не ломаются. `xargs -P 4` запускает команды параллельно.

## Частые вопросы на собеседовании

- `"$@"` vs `"$*"`? → Отдельные аргументы против одной строки.
- Что делает `set -euo pipefail`? → Выход при ошибке, ошибка на неустановленных переменных, честный код конвейера.
- Почему переменная, изменённая в `cmd | while`, не видна после цикла? → Цикл выполняется в subshell.
- Разница между `> f 2>&1` и `2>&1 > f`? → Порядок: во втором случае stderr остаётся в терминале.
- Как вернуть строку из функции? → `echo` и `$(...)`, `return` только для кода.
- Код 127? → Команда не найдена.

## Шпаргалка

- Всегда `"$var"`, `"$@"`; `local` в функциях
- `set -euo pipefail`, `trap 'cleanup' EXIT`
- `[[ ]]` для условий, `(( ))` для арифметики
- `> f 2>&1`, `&>`, `2>/dev/null`, `<<'EOF'`, `< <(cmd)`
- `${v:-d}`, `${v:=d}`, `${f%.*}`, `${p##*/}`, `${v//a/b}`
- `grep -rn`, `sed -i 's/a/b/g'`, `awk '{print $1}'`, `find -print0 | xargs -0`
- `shellcheck script.sh` — статический анализ скриптов
