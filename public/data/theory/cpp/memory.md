Главное отличие C++ от C в работе с памятью — идиома RAII: ресурс принадлежит объекту и освобождается его деструктором автоматически. На собеседовании проверяют, понимаете ли вы ссылки и категории значений, когда вызываются деструкторы, чем отличаются умные указатели и зачем нужны правила 0/3/5.

## Ссылки и указатели

Ссылка — псевдоним существующего объекта. Она обязана быть инициализирована, не может быть «нулевой» и не перепривязывается. Указатель — самостоятельный объект с адресом, который можно менять, обнулять и использовать в арифметике.

```cpp
int a = 1, b = 2;
int& r = a;      // r — другое имя для a
r = b;           // это присваивание a = 2, а не перепривязка
int* p = &a;
p = &b;          // указатель перенаправлен
p = nullptr;     // допустимо, «нулевой ссылки» не бывает
```

Передача по `const T&` избегает копирования и принимает временные объекты. Привязка временного объекта к `const T&` или `T&&` продлевает его жизнь до конца жизни ссылки.

## lvalue и rvalue

| Категория | Что это | Примеры |
|---|---|---|
| lvalue | объект с идентичностью, можно взять адрес | `x`, `*p`, `arr[i]`, `++x`, вызов функции, возвращающей `T&` |
| prvalue | «чистое» временное значение | `42`, `x + 1`, вызов функции, возвращающей `T` |
| xvalue | объект, из которого можно забрать ресурсы | `std::move(x)`, вызов функции, возвращающей `T&&` |

`T&` привязывается только к lvalue, `const T&` — к чему угодно, `T&&` — к rvalue (prvalue и xvalue). Именно на этом основана перегрузка конструкторов копирования и перемещения.

## RAII и деструкторы

Деструктор локального объекта вызывается при выходе из его области видимости, в том числе при исключении. Объекты уничтожаются в порядке, обратном созданию.

```cpp
class File {
    FILE* f_;
public:
    explicit File(const char* path) : f_(std::fopen(path, "r")) {
        if (!f_) throw std::runtime_error("open failed");
    }
    ~File() { std::fclose(f_); }
    File(const File&) = delete;             // владелец уникален
    File& operator=(const File&) = delete;
};

void read() {
    File f("data.txt");
    parse(f);        // даже если parse бросит исключение, файл закроется
}
```

Когда летит исключение, происходит **раскрутка стека**: уничтожаются все полностью сконструированные локальные объекты между `throw` и подходящим `catch`. Если деструктор во время раскрутки сам бросит исключение, вызывается `std::terminate`. Поэтому деструкторы не должны бросать — с C++11 они неявно `noexcept`.

> Деструктор вызывается только для полностью сконструированных объектов. Если конструктор бросил исключение, его деструктор не вызовется, но уже созданные члены и базы будут уничтожены. Поэтому каждый ресурс оборачивайте в отдельный RAII-член.

## new/delete и умные указатели

`new` выделяет память и вызывает конструктор, `delete` вызывает деструктор и освобождает память. `new T[n]` парно освобождается только через `delete[]`, иначе UB. В современном коде голые `new` и `delete` почти не пишут.

| Тип | Владение | Копирование | Накладные расходы |
|---|---|---|---|
| `unique_ptr<T>` | единоличное | запрещено, только move | как у сырого указателя |
| `shared_ptr<T>` | совместное, счётчик ссылок | разрешено | control block, атомарный счётчик |
| `weak_ptr<T>` | не владеет | разрешено | ссылка на control block |

```cpp
auto u = std::make_unique<Widget>(42);
auto u2 = std::move(u);            // u теперь пустой

auto s = std::make_shared<Widget>(1);
auto s2 = s;                       // use_count() == 2
std::weak_ptr<Widget> w = s;       // счётчик не растёт
if (auto locked = w.lock()) {      // shared_ptr или пустой
    locked->run();
}
```

`make_shared` делает одно выделение на объект и control block, `make_unique` и `make_shared` избавляют от голого `new` и безопасны при исключениях.

## Циклические ссылки

Два объекта, держащие друг друга через `shared_ptr`, никогда не удалятся: счётчики не упадут до нуля.

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;      // обратная ссылка — слабая
};
```

Типичный случай — родитель владеет детьми через `shared_ptr` или `unique_ptr`, а дети ссылаются на родителя через `weak_ptr` или сырой указатель.

## Правила 0, 3 и 5

- **Правило трёх**: если класс определяет деструктор, копирующий конструктор или копирующее присваивание, скорее всего нужны все три.
- **Правило пяти**: в C++11 к ним добавляются перемещающий конструктор и перемещающее присваивание. Пользовательский деструктор подавляет неявные move-операции, и «перемещение» молча становится копированием.
- **Правило нуля**: лучше не писать ни одной — храните ресурсы в `unique_ptr`, `vector`, `string`, и сгенерированные операции будут корректны.

```cpp
struct A {
    A(const A&);              // A b = a;  — копирующий конструктор
    A& operator=(const A&);   // c = a;    — копирующее присваивание
};
```

`A b = a;` — это инициализация, вызывается конструктор, несмотря на знак `=`.

## Частые вопросы на собеседовании

- Чем ссылка отличается от указателя? → Ссылку нельзя перепривязать или сделать нулевой, она обязана быть инициализирована.
- Что такое RAII? → Владение ресурсом привязано к времени жизни объекта, освобождение происходит в деструкторе.
- Когда использовать `shared_ptr`, а когда `unique_ptr`? → По умолчанию `unique_ptr`; `shared_ptr` — только при реально совместном владении.
- Как разорвать цикл `shared_ptr`? → Сделать одну из ссылок `weak_ptr`.
- Почему деструктор не должен бросать исключения? → Во время раскрутки стека это приведёт к `std::terminate`.
- Что будет, если смешать `new[]` и `delete`? → Неопределённое поведение.

## Шпаргалка

- Голые `new` и `delete` заменяем на `make_unique` и `make_shared`.
- `new[]` → `delete[]`, `new` → `delete`.
- `unique_ptr` не копируется, только перемещается.
- Цикл `shared_ptr` — утечка; обратная ссылка должна быть `weak_ptr`.
- `const T&` продлевает жизнь временного объекта.
- Деструкторы вызываются в обратном порядке создания и не должны бросать.
- Правило нуля лучше правила пяти.
