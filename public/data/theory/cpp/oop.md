ООП в C++ сложнее, чем в Java или Python: здесь есть множественное наследование, объекты по значению (и связанная с ними срезка), а полиморфизм работает только для виртуальных функций и только через указатели или ссылки. На собеседовании любят вопросы про порядок конструирования, vtable, виртуальный деструктор и ромбовидное наследование.

## Классы и модификаторы доступа

`class` и `struct` различаются только доступом по умолчанию: у `class` члены и наследование private, у `struct` — public.

| Спецификатор | Доступ из класса | Из наследника | Снаружи |
|---|---|---|---|
| `public` | да | да | да |
| `protected` | да | да | нет |
| `private` | да | нет | нет |

`friend` даёт другой функции или классу доступ к закрытым членам. Дружба односторонняя, не наследуется и не транзитивна.

Константный метод (`int size() const`) обещает не менять объект, только такие методы можно вызывать у `const`-объектов и по `const T&`. Поля с `mutable` можно менять даже в const-методах (например, кэш или мьютекс).

## Конструирование и уничтожение

Порядок конструирования: базовые классы (в порядке объявления в списке наследования) → члены (в порядке **объявления в классе**) → тело конструктора. Деструкторы вызываются строго в обратном порядке.

```cpp
struct S {
    int a;
    int b;
    S() : b(2), a(b + 1) {}   // ошибка: a инициализируется первым,
};                            // b ещё не инициализирован
```

Порядок в списке инициализации ни на что не влияет, флаг `-Wall` (`-Wreorder`) предупреждает о расхождении. Члены-константы, ссылки и члены без конструктора по умолчанию можно инициализировать только в списке инициализации.

## Виртуальные функции и vtable

Функция, объявленная `virtual`, вызывается по динамическому типу объекта, если вызов идёт через указатель или ссылку. Обычная функция связывается статически, по типу выражения.

```cpp
struct Shape {
    virtual double area() const = 0;   // чисто виртуальная
    virtual ~Shape() = default;        // обязателен для полиморфной базы
};
struct Circle final : Shape {
    double r;
    explicit Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
};

std::unique_ptr<Shape> s = std::make_unique<Circle>(2.0);
s->area();          // Circle::area через vtable
s->Shape::area();   // квалифицированный вызов — статический
```

Реализация во всех основных компиляторах: у каждого полиморфного класса есть таблица виртуальных функций (**vtable**), а в каждом объекте — скрытый указатель на неё (**vptr**). Виртуальный вызов — косвенный переход через таблицу.

- `override` — компилятор проверит, что метод действительно переопределяет виртуальный.
- `final` — запрет дальнейшего переопределения метода или наследования от класса.
- Класс с хотя бы одной чисто виртуальной функцией (`= 0`) абстрактный: его нельзя создать. Чисто виртуальная функция может иметь тело, а чисто виртуальный деструктор обязан его иметь.

## Ловушки полиморфизма

**Невиртуальный деструктор.** `delete` объекта-наследника через указатель на базу без `virtual ~Base()` — UB: на практике деструктор наследника не вызывается.

**Виртуальный вызов из конструктора.** Пока работает конструктор `Base`, объект имеет тип `Base`, и вызов уйдёт в `Base::f`, а не в наследника. То же в деструкторе.

**Срезка (slicing).** При копировании наследника в объект базового типа по значению копируется только часть базы.

```cpp
void print(Base b);          // срезка: внутри всегда Base
void print(const Base& b);   // полиморфизм сохраняется
```

**Сокрытие имён.** Метод `f(double)` в наследнике скрывает все перегрузки `f` из базы. Вернуть их можно через `using Base::f;`.

## Множественное и виртуальное наследование

При ромбовидном наследовании без `virtual` в объекте две копии общей базы, и обращение к её членам неоднозначно.

```cpp
struct A { int x = 0; };
struct B : virtual A {};
struct C : virtual A {};
struct D : B, C {};

D d;
d.x = 1;     // OK: подобъект A один
```

С виртуальным наследованием общий подобъект один, а его конструктор вызывает самый производный класс (`D`). Плата — дополнительные указатели или смещения в объекте и косвенный доступ к базе.

## Перегрузка операторов

Перегружать можно почти все операторы, кроме `::`, `.`, `.*`, `?:`, `sizeof` и `typeid`. Операторы `=`, `[]`, `()` и `->` — только как методы. Симметричные бинарные операторы и `<<` для потоков обычно делают свободными функциями.

```cpp
struct Vec {
    double x, y;
    Vec& operator+=(const Vec& o) { x += o.x; y += o.y; return *this; }
    bool operator==(const Vec&) const = default;   // C++20
};
Vec operator+(Vec a, const Vec& b) { return a += b; }
std::ostream& operator<<(std::ostream& os, const Vec& v) {
    return os << '(' << v.x << ", " << v.y << ')';
}
```

## Частые вопросы на собеседовании

- Зачем виртуальный деструктор? → Чтобы `delete` через указатель на базу вызвал деструктор наследника; без него это UB.
- Как работает виртуальный вызов? → Через vptr объекта и vtable класса.
- Что будет при вызове виртуальной функции из конструктора? → Вызовется версия текущего конструируемого класса, а не наследника.
- Что такое object slicing? → Потеря части наследника при копировании в объект базового типа по значению.
- Как решить проблему ромба? → Виртуальным наследованием общей базы.
- Чем `struct` отличается от `class`? → Только доступом по умолчанию.

## Шпаргалка

- База конструируется первой и уничтожается последней.
- Члены инициализируются в порядке объявления в классе.
- Полиморфная база → `virtual ~Base()`.
- Полиморфизм — только через указатель или ссылку, по значению — срезка.
- Всегда пишите `override`, при необходимости — `final`.
- Виртуальные функции в конструкторе и деструкторе не диспетчеризуются в наследника.
- Ромб без `virtual` — две копии базы.
