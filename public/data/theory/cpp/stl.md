STL (стандартная библиотека шаблонов) — это контейнеры, итераторы и алгоритмы, которые работают друг с другом через итераторы. На собеседовании ждут, что вы знаете сложность основных операций, понимаете, как устроены `vector`, `map` и `unordered_map`, и помните, когда итераторы становятся недействительными.

## vector: size, capacity и перевыделение

`std::vector` хранит элементы в одном непрерывном буфере. `size()` — сколько элементов, `capacity()` — сколько поместится без перевыделения. Когда место кончается, `push_back` выделяет буфер в 1.5–2 раза больше и переносит элементы, поэтому вставка в конец — амортизированная O(1).

```cpp
std::vector<int> v;
v.reserve(100);          // capacity >= 100, size == 0
for (int i = 0; i < 100; ++i)
    v.push_back(i);      // ни одного перевыделения
v.resize(10);            // size == 10, capacity не уменьшилась
v.shrink_to_fit();       // просьба освободить лишнее (не обязательная)
```

При переносе элементов `vector` использует move-конструктор, только если он `noexcept`, иначе копирует, чтобы сохранить строгую гарантию исключений.

`emplace_back(args...)` конструирует элемент прямо в буфере из аргументов конструктора, `push_back(obj)` копирует или перемещает готовый объект.

## Инвалидация итераторов

| Контейнер | Что инвалидирует итераторы |
|---|---|
| `vector`, `string` | любое перевыделение — все; `insert`/`erase` — начиная с позиции |
| `deque` | вставка в начало или конец — все итераторы (ссылки остаются); вставка в середину — всё |
| `list`, `map`, `set` | только итераторы на удалённые элементы |
| `unordered_*` | rehash — все итераторы (ссылки остаются); `erase` — только удалённые |

```cpp
std::vector<int> v{1, 2, 2, 3};
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 2) it = v.erase(it);   // erase возвращает следующий
    else ++it;
}
```

> Ссылка `int& r = v[0]` или `std::string_view` на строку тоже «висят» после перевыделения или уничтожения владельца. Это не ошибка компиляции, а UB во время выполнения.

## Ассоциативные контейнеры

`std::map` и `std::set` — сбалансированные деревья поиска (обычно красно-чёрные): ключи упорядочены, операции O(log n), нужен `operator<`. `std::unordered_map` и `std::unordered_set` — хеш-таблицы: O(1) в среднем, O(n) в худшем случае, порядок не определён, нужны `std::hash` и `operator==`.

```cpp
std::map<std::string, int> m;
m["a"] = 1;                 // operator[] вставит ключ, если его нет
if (m.contains("b")) {}     // C++20; ключ не вставляется
auto it = m.find("a");      // end(), если не найден
int x = m.at("a");          // бросит out_of_range, если ключа нет
```

`std::priority_queue` — адаптер над кучей, по умолчанию max-куча: `top()` возвращает наибольший элемент. Для min-кучи передают `std::greater<int>`.

## Таблица сложности

| Контейнер | Доступ по индексу | Поиск | Вставка/удаление |
|---|---|---|---|
| `vector` | O(1) | O(n) | O(1) амортиз. в конце, O(n) в середине |
| `deque` | O(1) | O(n) | O(1) в начале и конце |
| `list` | O(n) | O(n) | O(1) по известному итератору |
| `map` / `set` | — | O(log n) | O(log n) |
| `unordered_map` | — | O(1) в среднем | O(1) в среднем |
| `priority_queue` | — | только `top()` O(1) | O(log n) |

## Итераторы и алгоритмы

Категории итераторов (от слабых к сильным): input/output → forward (`forward_list`, `unordered_*`) → bidirectional (`list`, `map`, `set`) → random access (`vector`, `deque`, `array`) → contiguous (`vector`, `array`, `string`). Алгоритм указывает минимальную категорию: `std::sort` требует random access, поэтому для `list` есть собственный метод `list::sort()`.

`std::remove` и `std::remove_if` ничего не удаляют: они сдвигают оставшиеся элементы в начало и возвращают новый логический конец. Нужна идиома **remove-erase**.

```cpp
std::vector<int> v{1, 2, 3, 4, 5, 6};
v.erase(std::remove_if(v.begin(), v.end(),
                       [](int x) { return x % 2 == 0; }),
        v.end());                       // 1 3 5
std::erase_if(v, [](int x) { return x > 3; });   // C++20

std::sort(v.begin(), v.end());
auto lo = std::lower_bound(v.begin(), v.end(), 3);  // первый >= 3
auto hi = std::upper_bound(v.begin(), v.end(), 3);  // первый > 3
```

`lower_bound` и `upper_bound` работают за O(log n) только на отсортированном диапазоне.

## string, string_view и span

`std::string` владеет своими данными, у коротких строк обычно срабатывает SSO — символы хранятся внутри объекта без выделения в куче. `std::string_view` и `std::span<T>` (C++20) — невладеющие «окна»: указатель плюс длина. Они дешёвые для передачи в функции, но не продлевают жизнь данных.

```cpp
std::string_view bad() {
    std::string s = "temporary";
    return s;                 // висячий view: s уничтожится
}

void process(std::span<const int> data);   // примет vector, array, C-массив
```

## Частые вопросы на собеседовании

- Чем `map` отличается от `unordered_map`? → Дерево с порядком и O(log n) против хеш-таблицы с O(1) в среднем без порядка.
- Почему `push_back` — амортизированная O(1)? → Ёмкость растёт геометрически, редкие копирования за O(n) размазываются по всем вставкам.
- Что делает `std::remove`? → Сдвигает элементы и возвращает новый конец, размер не меняется; нужен `erase`.
- Когда инвалидируются итераторы `vector`? → При перевыделении — все, при `insert`/`erase` — начиная с позиции.
- `emplace_back` или `push_back`? → `emplace_back` конструирует на месте из аргументов; для готового объекта разницы почти нет.
- Опасность `string_view`? → Висячая ссылка, если владелец строки умер раньше.

## Шпаргалка

- Знаете размер заранее — `reserve`.
- `m[key]` вставляет ключ; для проверки — `find`, `contains`.
- remove-erase или `std::erase_if` в C++20.
- `erase` в цикле: `it = v.erase(it)`.
- `priority_queue` — max-куча по умолчанию.
- `std::sort` требует random access итераторы.
- `string_view` и `span` не владеют данными.
