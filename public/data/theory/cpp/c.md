C — язык «близко к железу»: программист сам управляет памятью, а компилятор почти ничего не проверяет. На собеседовании по C и C++ почти всегда спрашивают про указатели, массивы, строки, динамическую память и неопределённое поведение (UB), потому что именно там живут самые дорогие баги: утечки, падения и уязвимости.

## Указатели и арифметика указателей

Указатель хранит адрес объекта. Арифметика идёт в единицах типа: `p + 1` сдвигает адрес на `sizeof(*p)` байт. Разность двух указателей внутри одного массива — число элементов между ними.

```c
int a[] = {10, 20, 30, 40};
int *p = a;            // массив распадается в указатель на a[0]
p += 2;
printf("%d %d\n", *p, *(p - 1));   // 30 20
printf("%td\n", p - a);            // 2
```

Модификатор `const` читается справа налево:

| Объявление | Можно менять указатель | Можно менять `*p` |
|---|---|---|
| `const int *p` | да | нет |
| `int *const p` | нет | да |
| `const int *const p` | нет | нет |

## Массивы, sizeof и строки

Массив почти везде **распадается** (decay) в указатель на первый элемент: при передаче в функцию, в арифметике, при присваивании указателю. Исключения — `sizeof`, `&a` и инициализация строковым литералом. Поэтому размер массива внутри функции узнать нельзя, его передают отдельным параметром.

```c
void f(int a[10]) {            // на самом деле int *a
    printf("%zu\n", sizeof a); // 8 — размер указателя
}

int a[10];
printf("%zu\n", sizeof a);     // 40
size_t n = sizeof a / sizeof a[0];   // 10 — работает только для массива
```

Строка в C — массив `char`, завершённый нулевым символом `'\0'`. `strlen` его не считает, а память под него нужна: копия строки занимает `strlen(s) + 1` байт.

> `strcpy` не знает размер буфера и легко пишет за его границу. `strncpy` не ставит `'\0'`, если строка не поместилась. Безопаснее `snprintf(dst, sizeof dst, "%s", src)`.

## Динамическая память

| Функция | Что делает |
|---|---|
| `malloc(n)` | выделяет n байт, содержимое не инициализировано |
| `calloc(cnt, size)` | выделяет `cnt * size` байт и обнуляет их |
| `realloc(p, n)` | меняет размер блока, может перенести его по другому адресу |
| `free(p)` | освобождает блок; `free(NULL)` ничего не делает |

```c
int *buf = malloc(10 * sizeof *buf);
if (!buf) return -1;

int *tmp = realloc(buf, 20 * sizeof *buf);
if (!tmp) { free(buf); return -1; }   // старый блок жив, не теряем его
buf = tmp;

free(buf);
buf = NULL;                           // защита от double free и висячего указателя
```

Типичные ошибки:

- **утечка** — потерян последний указатель на блок, `free` не вызван;
- **double free** — повторный `free` того же блока (UB);
- **use-after-free и висячий указатель** — обращение к освобождённой памяти или к локальной переменной завершившейся функции;
- **выход за границы** — запись `buf[n]` при размере n.

Стек хранит локальные (автоматические) переменные: он быстрый, но небольшой (обычно 1–8 МБ), и память освобождается при выходе из функции. Куча большая, временем жизни её блоков управляет программист.

## Неопределённое поведение

UB — это поведение, на которое стандарт не накладывает никаких требований. Программа может работать «как ожидалось», упасть или вести себя странно только с `-O2`. Компилятор вправе считать, что UB никогда не происходит, и оптимизировать код исходя из этого.

```c
int x = INT_MAX;
x + 1;                 // UB: переполнение знакового
unsigned u = 0;
u - 1;                 // OK: UINT_MAX, арифметика по модулю 2^N

int a[5];
a[5] = 1;              // UB: выход за границу
int y;
printf("%d", y);       // UB: чтение неинициализированной переменной
int i = 1;
i = i++ + ++i;         // UB: несколько изменений без точки следования
```

## Выравнивание структур, static и extern

Поля структуры выравниваются по своему размеру, поэтому компилятор вставляет паддинг. Сортировка полей по убыванию размера уменьшает структуру.

```c
struct A { char a; int b; char c; };   // 12 байт на x86-64
struct B { int b; char a; char c; };   // 8 байт
```

- `static` у глобального имени — внутреннее связывание, имя видно только в этом .c файле.
- `static` у локальной переменной — она живёт всю программу и сохраняет значение между вызовами.
- `extern int x;` — объявление без определения: переменная определена в другом файле.
- Глобальные и `static` переменные без инициализатора обнуляются.

## Ловушки макросов

Макрос — текстовая подстановка до компиляции, без учёта типов и приоритетов.

```c
#define SQUARE(x) x * x
SQUARE(2 + 3)          // 2 + 3 * 2 + 3 = 11

#define SQUARE2(x) ((x) * (x))
SQUARE2(i++)           // i++ вычисляется дважды — UB
```

Правило: каждый параметр и всё выражение — в скобках, аргументы без побочных эффектов, а лучше `static inline` функция.

## Частые вопросы на собеседовании

- Чем массив отличается от указателя? → Массив — блок элементов фиксированного размера, указатель — переменная с адресом; массив распадается в указатель почти везде, кроме `sizeof` и `&`.
- Почему `sizeof(arr)` внутри функции даёт 8? → Параметр-массив на самом деле указатель.
- Что такое висячий указатель? → Указатель на освобождённую или уже не существующую память; его разыменование — UB.
- Чем `malloc` отличается от `calloc`? → `calloc` обнуляет память и принимает число элементов и их размер отдельно.
- Переполнение `int` и `unsigned` — в чём разница? → Знаковое — UB, беззнаковое определено по модулю 2^N.
- Зачем паддинг в структурах? → Для выравнивания полей; невыровненный доступ медленнее или вообще невозможен.

## Шпаргалка

- `p + n` сдвигает адрес на `n * sizeof(*p)` байт.
- Под копию строки нужно `strlen(s) + 1` байт.
- Каждому `malloc` — ровно один `free`, после него `p = NULL`.
- `tmp = realloc(p, n)`, а не `p = realloc(p, n)`.
- Знаковое переполнение, выход за границы, чтение неинициализированной переменной, `i = i++` — UB.
- `const int *` — нельзя писать через указатель; `int *const` — нельзя перенаправить указатель.
- Аргументы макросов — в скобки, или пишите `static inline`.
