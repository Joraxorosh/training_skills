В этой теме две части, которые на собеседовании часто идут вместе: многопоточность (потоки, мьютексы, атомики, модель памяти) и то, как C++ код превращается в исполняемый файл (этапы сборки, линковка, библиотеки, CMake, санитайзеры). Обе части про «невидимые» ошибки, которые не ловит компилятор.

## Потоки и data race

`std::thread` запускает функцию в новом потоке. До уничтожения объекта нужно вызвать `join()` (дождаться) или `detach()` (отпустить), иначе деструктор вызовет `std::terminate`. C++20 `std::jthread` делает `join` в деструкторе сам.

```cpp
int counter = 0;                       // гонка
std::atomic<int> safe{0};              // без гонки

void work() {
    for (int i = 0; i < 100000; ++i) {
        ++counter;                     // UB: data race
        ++safe;                        // атомарный fetch_add
    }
}

std::thread t1(work), t2(work);
t1.join();
t2.join();                             // safe == 200000
```

**Data race** — одновременный доступ двух потоков к одной ячейке памяти, хотя бы один — запись, без синхронизации. Это UB, а не просто «неточный результат»: компилятор оптимизирует код, считая, что гонок нет.

## Мьютексы и блокировки

| Обёртка | Особенности |
|---|---|
| `std::lock_guard` | простейший RAII: захват в конструкторе, освобождение в деструкторе |
| `std::unique_lock` | можно `unlock()` и `lock()`, `defer_lock`, перемещать; нужен для `condition_variable` |
| `std::scoped_lock` | C++17, захватывает несколько мьютексов сразу без deadlock |
| `std::shared_lock` | совместное (читательское) владение `shared_mutex` |

**Deadlock** возникает, когда потоки захватывают мьютексы в разном порядке и ждут друг друга. Защита: единый порядок захвата, `std::scoped_lock(a, b)`, не вызывать чужой код под мьютексом, держать блокировку как можно меньше.

```cpp
std::mutex m;
std::condition_variable cv;
bool ready = false;

void consumer() {
    std::unique_lock lk(m);
    cv.wait(lk, [] { return ready; });   // предикат — защита от ложных пробуждений
}

void producer() {
    { std::lock_guard lk(m); ready = true; }
    cv.notify_one();
}
```

`wait` может вернуться без `notify` (spurious wakeup), а условие могут «перехватить» другие потоки, поэтому его всегда перепроверяют.

## Атомики и порядок памяти

`std::atomic<T>` гарантирует неделимость операций. Параметр `memory_order` определяет, как они упорядочены относительно остальных обращений к памяти.

- `seq_cst` (по умолчанию) — единый глобальный порядок всех таких операций, самый простой для рассуждений.
- `release` при записи и `acquire` при чтении — если чтение увидело записанное значение, все записи до `release` видны после `acquire`.
- `relaxed` — только атомарность, подходит для счётчиков статистики.

```cpp
int data = 0;
std::atomic<bool> ready{false};
// поток 1
data = 42;
ready.store(true, std::memory_order_release);
// поток 2
while (!ready.load(std::memory_order_acquire)) {}
assert(data == 42);                     // гарантировано
```

## Как собирается программа

1. **Препроцессор** раскрывает `#include`, `#define`, `#if` — получается единица трансляции.
2. **Компилятор** превращает её в ассемблер, здесь же проверяются типы и синтаксис.
3. **Ассемблер** создаёт объектный файл (`.o`, `.obj`) с таблицей символов.
4. **Линковщик** связывает объектные файлы и библиотеки в исполняемый файл.

Заголовки содержат объявления, .cpp файлы — определения. Include guards или `#pragma once` защищают от двойного включения **в одну** единицу трансляции. **ODR** (правило одного определения): функция или переменная с внешним связыванием определяется в программе ровно один раз. Определение обычной функции в заголовке, включённом в два .cpp, — ошибка `multiple definition`. Решения: `inline`, шаблон или перенос в .cpp.

| Ошибка | Этап | Типичная причина |
|---|---|---|
| `expected ';'`, `no matching function` | компиляция | синтаксис, типы |
| `undefined reference to 'foo'` | линковка | нет определения, не подключена библиотека, разные сигнатуры |
| `multiple definition of 'foo'` | линковка | определение в заголовке без `inline` |
| `cannot open shared object file` | запуск | динамическая библиотека не найдена |

Статическая библиотека (`.a`, `.lib`) копируется в исполняемый файл при линковке. Динамическая (`.so`, `.dll`) загружается при запуске или через `dlopen`, разделяется между процессами и обновляется без пересборки программы, если не сломан ABI.

## CMake, флаги и санитайзеры

```cmake
cmake_minimum_required(VERSION 3.20)
project(app CXX)
set(CMAKE_CXX_STANDARD 20)

add_library(core STATIC src/core.cpp)
target_include_directories(core PUBLIC include)

add_executable(app src/main.cpp)
target_link_libraries(app PRIVATE core)
target_compile_options(app PRIVATE -Wall -Wextra)
```

`PRIVATE` — зависимость нужна только самой цели, `PUBLIC` — передаётся и её потребителям, `INTERFACE` — только потребителям.

- `-Wall -Wextra` — основные предупреждения, `-Werror` превращает их в ошибки.
- `-O0 -g` — отладка, `-O2` — релиз. С `-O2` UB «стреляет» чаще: например, `x + 1 > x` для `int` превращается в `true`.
- `-fsanitize=address` (ASan) — выход за границы, use-after-free, утечки.
- `-fsanitize=undefined` (UBSan) — знаковое переполнение, неверные сдвиги и другое UB.
- `-fsanitize=thread` (TSan) — гонки данных; несовместим с ASan в одной сборке.

## Частые вопросы на собеседовании

- Что будет, если не вызвать `join` или `detach`? → `std::terminate` в деструкторе `std::thread`.
- Зачем предикат в `cv.wait`? → Защита от ложных пробуждений и уже изменившегося условия.
- Как избежать deadlock? → Единый порядок захвата, `std::scoped_lock`, короткие критические секции.
- Чем `undefined reference` отличается от ошибки компиляции? → Это ошибка линковщика: объявление есть, определения нет.
- Что такое ODR? → Одно определение на программу для сущностей с внешним связыванием (`inline` и шаблоны — одинаковые определения в разных единицах трансляции).
- Статическая или динамическая библиотека? → Статическая проще в развёртывании, динамическая экономит память и обновляется отдельно.

## Шпаргалка

- Data race — UB; общие данные защищайте мьютексом или делайте `atomic`.
- RAII-блокировки: `lock_guard`, `unique_lock`, `scoped_lock`.
- `cv.wait(lock, predicate)` — всегда с предикатом.
- release/acquire — публикация данных между потоками.
- Препроцессор → компиляция → ассемблер → линковка.
- Определение функции в заголовке — только `inline`.
- В тестовых сборках — `-Wall -Wextra` и ASan/UBSan/TSan.
