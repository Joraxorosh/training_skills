Java — объектно-ориентированный язык с одиночным наследованием классов, множественной реализацией интерфейсов и строгими правилами видимости. На собеседовании проверяют не определения, а механику: какой метод будет вызван, что генерирует `record`, почему ломается `HashSet` и зачем нужны sealed-иерархии.

## Инкапсуляция и модификаторы доступа

Инкапсуляция — сокрытие состояния за методами. Поля делают `private` и открывают только нужное поведение.

| Модификатор | Класс | Пакет | Подкласс | Везде |
|---|---|---|---|---|
| `private` | да | нет | нет | нет |
| без модификатора | да | да | нет | нет |
| `protected` | да | да | да | нет |
| `public` | да | да | да | да |

Неизменяемый класс: поля `private final`, нет сеттеров, класс `final`, а изменяемые входные данные копируются защитно. Такие объекты потокобезопасны и надёжны в роли ключей.

## Наследование и конструкторы

Первая инструкция любого конструктора — `super(...)` или `this(...)`, явный или неявный. Поэтому конструкторы выполняются от корня иерархии к листу. Поля подкласса инициализируются **после** возврата из конструктора родителя.

```java
class Base {
    Base() { print(); }                 // вызов переопределяемого метода — ловушка
    void print() { System.out.println("Base"); }
}
class Derived extends Base {
    private int x = 42;
    @Override void print() { System.out.println("Derived " + x); }
}

new Derived();   // Derived 0 — поле x ещё не инициализировано
```

## Полиморфизм: перегрузка и переопределение

**Перегрузка** (overloading) — одно имя, разные параметры. Выбор делает компилятор по **статическим** типам аргументов. **Переопределение** (overriding) — та же сигнатура в подклассе. Выбор делает JVM по **реальному** типу объекта (динамическое связывание).

```java
static String f(Object o) { return "Object"; }
static String f(String s) { return "String"; }

Object o = "hello";
f(o);        // "Object" — статический тип Object
f(null);     // "String" — выбирается наиболее специфичная перегрузка

class Parent { static String who() { return "P"; } String name() { return "P"; } }
class Child extends Parent { static String who() { return "C"; } String name() { return "C"; } }

Parent p = new Child();
p.who();     // "P" — static связывается по типу ссылки
p.name();    // "C" — виртуальный вызов
```

Поля тоже не полиморфны: поле с тем же именем в подклассе лишь скрывает родительское, и `ref.field` выбирается по типу ссылки. Аннотация `@Override` заставляет компилятор проверить, что метод действительно переопределяет родительский.

## Абстрактные классы и интерфейсы

| | Абстрактный класс | Интерфейс |
|---|---|---|
| Наследование | один | сколько угодно |
| Состояние | любые поля | только `public static final` |
| Конструктор | есть | нет |
| Методы с телом | любые | `default`, `static`, `private` |
| Назначение | общая реализация | контракт, роль |

Если два интерфейса дают одинаковый `default`-метод, класс обязан его переопределить, а внутри может вызвать нужную версию через `X.super.hello()`.

## equals, hashCode и toString

Контракт: равные по `equals` объекты **обязаны** иметь одинаковый `hashCode`. Обратное не требуется. Если переопределить только `equals`, `HashSet` посчитает «равные» объекты разными, потому что сравнивает хеши раньше, чем вызывает `equals`.

```java
public final class Point {
    private final int x, y;
    public Point(int x, int y) { this.x = x; this.y = y; }

    @Override public boolean equals(Object o) {
        if (this == o) return true;
        return o instanceof Point p && p.x == x && p.y == y;
    }
    @Override public int hashCode() { return Objects.hash(x, y); }
    @Override public String toString() { return "Point[x=" + x + ", y=" + y + "]"; }
}
```

Без переопределения `toString()` возвращает `ClassName@hexHash`.

## Records, sealed и pattern matching

`record` (Java 16) генерирует `private final` поля, канонический конструктор, аксессоры `x()`, а также `equals`, `hashCode` и `toString`. Record неявно `final` и может реализовывать интерфейсы. **Sealed**-типы (Java 17) перечисляют допустимых наследников, и каждый из них объявляется `final`, `sealed` или `non-sealed`. Вместе с **pattern matching for switch** (Java 21) это даёт алгебраические типы данных с проверкой полноты.

```java
sealed interface Shape permits Circle, Square {}
record Circle(double r) implements Shape {}
record Square(double side) implements Shape {}

static double area(Shape s) {
    return switch (s) {                       // default не нужен
        case Circle c when c.r() == 0 -> 0;
        case Circle c -> Math.PI * c.r() * c.r();
        case Square(double side) -> side * side;   // record pattern
    };
}

if (obj instanceof String str && str.length() > 3) {
    System.out.println(str.toUpperCase());    // str виден только здесь
}
```

## SOLID коротко

- **S**ingle Responsibility — у класса одна причина для изменения.
- **O**pen/Closed — расширяем новыми классами, а не правкой старых.
- **L**iskov Substitution — подтип заменяет базовый тип без нарушения контракта (классический контрпример: `Square extends Rectangle`).
- **I**nterface Segregation — узкие интерфейсы вместо «толстых».
- **D**ependency Inversion — зависим от абстракций, их внедряет DI-контейнер.

## Частые вопросы на собеседовании

- Перегрузка или переопределение — что выбирается в рантайме? → переопределение; перегрузка выбирается при компиляции.
- Можно ли переопределить `static`-метод? → нет, только скрыть; связывание статическое.
- Что будет, если переопределить `equals` без `hashCode`? → хеш-коллекции перестанут находить равные объекты.
- Абстрактный класс или интерфейс? → интерфейс для контракта и множественной реализации, абстрактный класс для общего состояния и кода.
- Чем record отличается от обычного класса? → неизменяемый носитель данных с автогенерацией методов, не может наследовать класс.
- Зачем sealed? → закрытая иерархия, компилятор проверяет полноту `switch`.

## Шпаргалка

- Конструкторы выполняются от предка к потомку, поля потомка инициализируются после `super()`.
- Не вызывайте переопределяемые методы из конструктора.
- Перегрузка — по статическому типу, переопределение — по реальному.
- Поля и `static`-методы не полиморфны.
- `equals` + `hashCode` всегда вместе.
- `record` → аксессоры `x()`, а не `getX()`.
- Sealed + switch по шаблонам → `default` не нужен.
