Java — статически типизированный язык, в котором значения делятся на два мира: **примитивы** и **ссылки на объекты**. Большинство «каверзных» вопросов на собеседовании по основам вырастает из этой границы: кэш `Integer`, `==` против `equals`, неизменяемость `String` и то, как аргументы передаются в методы.

## Примитивы и обёртки

Примитивов восемь, их размер не зависит от платформы. У каждого есть класс-обёртка, а компилятор автоматически переводит одно в другое (**autoboxing** и **unboxing**).

| Тип | Размер | Обёртка | По умолчанию |
|---|---|---|---|
| `byte` | 8 бит | `Byte` | 0 |
| `short` | 16 бит | `Short` | 0 |
| `int` | 32 бита | `Integer` | 0 |
| `long` | 64 бита | `Long` | 0L |
| `float` / `double` | 32 / 64 бита | `Float` / `Double` | 0.0 |
| `char` | 16 бит (UTF-16) | `Character` | '\u0000' |
| `boolean` | не специфицирован | `Boolean` | false |

Автоупаковка вызывает `Integer.valueOf()`, который **кэширует значения от -128 до 127**. Поэтому `==` на обёртках работает «случайно» для маленьких чисел и ломается для больших:

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);       // true  — один объект из кэша
System.out.println(c == d);       // false — два разных объекта
System.out.println(c.equals(d));  // true

Long x = 10L;
System.out.println(x.equals(10)); // false — 10 упакован в Integer
System.out.println(x == 10);      // true  — распаковка и сравнение чисел
```

> Распаковка `null` даёт `NullPointerException`: `Integer n = null; int m = n;` упадёт. Это частая ошибка при работе с `Map<String, Integer>`.

## Арифметика: переполнение, char, деление

Целые числа переполняются молча, по модулю 2ⁿ. `char` — это число, и в выражениях он расширяется до `int`. Составное присваивание содержит скрытое приведение типа.

```java
int max = Integer.MAX_VALUE;
System.out.println(max + 1 == Integer.MIN_VALUE); // true
Math.addExact(max, 1);                             // ArithmeticException

char c = 'A';
System.out.println(c + 1);          // 66
System.out.println((char) (c + 1)); // B

short s = 10;
s += 5;        // ок: s = (short) (s + 5)
// s = s + 5;  // ошибка компиляции: int нельзя присвоить short

System.out.println(1.0 / 0);  // Infinity
System.out.println(0.0 / 0);  // NaN
System.out.println(1 / 0);    // ArithmeticException
```

## String, string pool и StringBuilder

`String` **неизменяем**: все «изменяющие» методы возвращают новую строку. Литералы хранятся в **string pool**, поэтому одинаковые литералы — один объект. `new String("x")` всегда создаёт новый объект. Строки сравнивают только через `equals()`.

```java
String s1 = "java";
String s2 = "java";
String s3 = new String("java");
System.out.println(s1 == s2);        // true
System.out.println(s1 == s3);        // false
System.out.println(s1 == s3.intern()); // true

String s = "abc";
s.toUpperCase();          // результат потерян
s = s.toUpperCase();      // так правильно
```

Конкатенация `final`-констант вычисляется при компиляции и попадает в пул, конкатенация обычных переменных происходит в рантайме. В цикле строки собирают через `StringBuilder`: каждое `+=` копирует всю строку, что даёт O(n²). `StringBuffer` — синхронизированная версия, нужна редко.

## Передача аргументов: только по значению

Java **всегда** передаёт аргументы по значению. Для объектов копируется значение ссылки: метод может изменить состояние объекта, но не может заменить объект у вызывающего.

```java
static void change(StringBuilder sb) {
    sb.append(" world");          // меняет общий объект
    sb = new StringBuilder("new"); // меняет только локальную копию ссылки
}

StringBuilder sb = new StringBuilder("hello");
change(sb);
System.out.println(sb);   // hello world
```

`final` у переменной запрещает переприсваивание, но не делает объект неизменяемым: в `final List` можно добавлять элементы. `static`-поле одно на класс, а `static`-метод не имеет `this` и не переопределяется, а только скрывается.

## Современный синтаксис: switch, var, text blocks

**Switch-выражения** (Java 14) возвращают значение, стрелочные ветки не проваливаются, а из блока значение возвращают через `yield`. В классическом `switch` с `case X:` без `break` выполнение проваливается в следующие ветки.

```java
String type = switch (day) {
    case 1, 7 -> "weekend";
    case 2, 3, 4, 5, 6 -> {
        String t = "work";
        yield t + "day";
    }
    default -> "unknown";
};

var list = new ArrayList<String>();  // тип ArrayList<String> выведен компилятором

String json = """
    {
      "name": "Ann"
    }
    """;   // общий отступ удаляется, результат — обычный String
```

`var` (Java 10) работает только для локальных переменных с инициализатором. Тип остаётся статическим, `var x = null;` не скомпилируется.

## Частые вопросы на собеседовании

- Почему `Integer 128 == Integer 128` даёт `false`? → `valueOf` кэширует только -128..127, а `==` сравнивает ссылки.
- Чем `==` отличается от `equals`? → `==` сравнивает значения примитивов или идентичность ссылок, `equals` — логическое равенство.
- Почему `String` неизменяем? → безопасность (ключи `HashMap`, пути, пароли), string pool, кэш хеша, потокобезопасность.
- Java передаёт объекты по ссылке? → нет, по значению; копируется значение ссылки.
- Что будет при `Integer.MAX_VALUE + 1`? → молчаливое переполнение в `Integer.MIN_VALUE`.
- Зачем `StringBuilder`? → изменяемый буфер, линейная сборка строки вместо квадратичной.

## Шпаргалка

- Обёртки сравнивать через `equals`, кэш `Integer` — от -128 до 127.
- Распаковка `null` → NPE.
- `String` неизменяем: результат методов надо присваивать.
- Литералы — в пуле, `new String` — новый объект.
- Аргументы передаются по значению, для объектов — копия ссылки.
- `final` ≠ неизменяемость объекта.
- `s += 1` для `short` компилируется, `s = s + 1` — нет.
- Целочисленное деление на 0 → `ArithmeticException`, вещественное → `Infinity`/`NaN`.
- Switch-выражения: `->` без проваливания, `yield` из блока.
