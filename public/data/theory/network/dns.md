DNS превращает имена в адреса и служит распределённой базой настроек домена: почта, сертификаты, верификации, обнаружение сервисов. Почти каждый инцидент «у части пользователей не работает» начинается с вопроса «а что с DNS и кэшами?». Рядом спрашивают про CDN, anycast и GeoDNS — механизмы, которые решают, к какому серверу попадёт пользователь.

## Как разрешается имя

Участники: **stub-резолвер** в ОС, **рекурсивный резолвер** (провайдера, `1.1.1.1`, `8.8.8.8`, корпоративный) и **авторитативные серверы**, хранящие зоны.

1. Приложение спрашивает ОС; она проверяет `/etc/hosts` (порядок задаёт `/etc/nsswitch.conf`, обычно `files dns`) и свой кэш.
2. Stub отправляет запрос рекурсивному резолверу.
3. Резолвер спрашивает корневой сервер и получает referral на серверы `.com`.
4. Серверы `.com` отдают referral на NS-серверы `example.com`.
5. Авторитативный сервер `example.com` возвращает ответ, резолвер его кэширует.

Если NS-серверы находятся внутри своей же зоны (`ns1.example.com`), родительская зона публикует их адреса — **glue-записи**, иначе возникнет циклическая зависимость.

## Типы записей

| Тип | Назначение | Пример |
|---|---|---|
| A / AAAA | IPv4 / IPv6-адрес | `example.com. A 93.184.216.34` |
| CNAME | Псевдоним другого имени | `www CNAME example.com.` |
| MX | Почтовые серверы, меньше число — выше приоритет | `MX 10 mx1.example.com.` |
| TXT | Текст: SPF, DKIM, DMARC, верификации | `TXT "v=spf1 include:_spf.google.com ~all"` |
| NS | Серверы, обслуживающие зону | `NS ns1.example.com.` |
| SOA | Параметры зоны: serial, refresh, retry, expire, minimum | |
| SRV | Хост и порт сервиса: priority weight port target | `_sip._tcp SRV 10 60 5060 sip1` |
| CAA | Какие CA могут выпускать сертификаты | `CAA 0 issue "letsencrypt.org"` |
| PTR | Обратное разрешение IP → имя | |

CNAME не может сосуществовать с другими записями того же имени, а на вершине зоны обязательны SOA и NS, поэтому CNAME на `example.com.` запрещён. Провайдеры обходят это через ALIAS/ANAME или CNAME flattening.

Serial в SOA должен расти при каждом изменении: secondary-серверы забирают зону (AXFR/IXFR), только если serial у primary больше.

## TTL и кэширование

TTL — сколько секунд резолвер может отдавать запись из кэша. Новое значение TTL резолвер узнает только после истечения старого, поэтому перед миграцией TTL снижают **заранее**, затем меняют запись, потом возвращают TTL.

Отрицательные ответы тоже кэшируются. **NXDOMAIN** — имени нет вовсе; **NOERROR с пустым ANSWER** — имя есть, но записи нужного типа нет. Время кэширования отрицательного ответа — минимум из TTL SOA и её поля minimum.

```bash
dig +short example.com AAAA          # только значения
dig example.com MX                   # полный ответ с секциями
dig @1.1.1.1 example.com +trace      # пройти цепочку от корня
dig -x 93.184.216.34                 # PTR
```

Во флагах ответа `aa` означает, что ответил авторитативный сервер, `rd`/`ra` — рекурсия запрошена/доступна, `tc` — ответ усечён.

## Транспорт и безопасность DNS

Обычные запросы идут по UDP/53. TCP/53 обязателен: если ответ не влез (флаг TC), для передачи зоны и для больших DNSSEC-ответов. EDNS0 увеличивает допустимый размер UDP-ответа.

| Технология | Что даёт | Чего не даёт |
|---|---|---|
| DoH (HTTPS, 443) | Шифрование «клиент — резолвер», маскировка под веб-трафик | Подлинность данных от авторитативного сервера |
| DoT (TLS, 853) | То же шифрование, легко отличим по порту | То же |
| DNSSEC | Подпись записей (RRSIG, DNSKEY, DS), цепочка доверия от корня | Шифрование |

Это не конкуренты, а дополняющие друг друга механизмы.

## CDN, anycast и GeoDNS

**CDN** кэширует контент на edge-серверах ближе к пользователю: меньше задержка, меньше нагрузка на origin, поглощение DDoS, терминация TLS. Направить пользователя к ближайшему узлу можно двумя способами.

- **Anycast** — один префикс анонсируется по BGP из многих точек, сеть сама приводит пакет в ближайшую по маршрутизации. Так работают `1.1.1.1`, корневые серверы и многие CDN.
- **GeoDNS** — авторитативный сервер отдаёт разные IP в зависимости от того, откуда пришёл запрос. Проблема: он видит адрес резолвера, а не клиента. Помогает **EDNS Client Subnet**: резолвер передаёт усечённую подсеть клиента.

> Публичные резолверы могут не отправлять ECS ради приватности, поэтому GeoDNS часто комбинируют с anycast.

## Частые вопросы на собеседовании

- Что происходит, когда вводишь адрес в браузере? → Кэши, hosts, рекурсивный резолвер, корень → TLD → авторитативный сервер, затем TCP/TLS/HTTP.
- Почему смена IP «доходит» не сразу? → Кэширование по TTL; снижайте TTL заранее.
- Можно ли CNAME на корень домена? → Нет, используйте ALIAS или CNAME flattening.
- DNS работает только по UDP? → Нет, TCP нужен для больших ответов и AXFR.
- DoH и DNSSEC — одно и то же? → Нет: шифрование канала против подписи данных.
- Чем anycast отличается от GeoDNS? → Маршрутизация BGP к одному IP против разных IP в ответе DNS.

## Шпаргалка

- Цепочка: hosts → stub → recursive → root → TLD → authoritative
- A, AAAA, CNAME, MX (меньше — приоритетнее), TXT, NS, SOA, SRV, CAA, PTR
- CNAME не на вершине зоны; glue для NS внутри зоны; serial растёт
- TTL снижать заранее; NXDOMAIN кэшируется по SOA
- UDP/53, TCP/53, DoT 853, DoH 443
- Anycast = BGP, GeoDNS + ECS
