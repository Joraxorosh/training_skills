Go — компилируемый язык со статической типизацией и намеренно маленьким синтаксисом. На собеседовании по основам обычно проверяют нулевые значения, способы объявления переменных, константы и `iota`, отсутствие неявных преобразований, устройство строк и правила видимости. Многие вопросы построены на коде, где одна деталь меняет результат.

## Объявление переменных и нулевые значения

Переменную объявляют через `var` или коротким объявлением `:=`. Второе работает только внутри функций и выводит тип из правой части.

```go
var a int           // 0
var s string        // ""
var p *int          // nil
b := 3.5            // float64
x, y := 1, "go"     // несколько сразу

var global = 10     // на уровне пакета только var/const/func/type
```

Неинициализированной памяти в Go нет: каждая переменная получает **нулевое значение** своего типа.

| Тип | Нулевое значение |
|---|---|
| числа | `0` |
| `bool` | `false` |
| `string` | `""` |
| указатель, slice, map, chan, func, interface | `nil` |
| struct | все поля — нулевые значения |

Неиспользуемая локальная переменная и неиспользуемый импорт — ошибки компиляции. Неиспользуемые переменные пакета разрешены.

## Константы и iota

Константы вычисляются на этапе компиляции. **Нетипизированные** константы имеют произвольную точность и получают тип только при использовании.

```go
const big = 1 << 100      // ок: пока это просто число
fmt.Println(big >> 98)    // 4

const c = 10
var f float64 = c / 4     // 2: целочисленное деление констант

const (
    A = iota  // 0
    B         // 1 — повторяется выражение iota
    _         // 2 — пропуск
    D         // 3
)

const (
    KB = 1 << (10 * (iota + 1))  // 1024
    MB                           // 1048576
)
```

`iota` равен номеру строки внутри блока `const`. Строка без выражения повторяет предыдущее выражение, а `iota` при этом продолжает расти.

## Типы и явные преобразования

Неявных преобразований нет — даже `int` в `float64` или `int` в `int64`. Именованные типы с одинаковой основой тоже несовместимы без явного преобразования.

```go
x := 10
var y float64 = float64(x)   // без float64(...) — ошибка компиляции

type Celsius float64
type Fahrenheit float64
var t Celsius = 100
// var f Fahrenheit = t      // ошибка
var f Fahrenheit = Fahrenheit(t*9/5 + 32)

var i8 int8 = 127
i8++                         // -128: переполнение во время выполнения заворачивается
```

Переполнение константы (`var b int8 = 128`) ловит компилятор, а переполнение во время выполнения молча заворачивается.

## Строки, byte и rune

Строка — неизменяемая последовательность **байтов**, обычно в UTF-8. `len` считает байты, индексация возвращает `byte` (`uint8`), а `range` декодирует руны (`rune` = `int32`, кодовая точка Unicode).

```go
s := "héllo"
fmt.Println(len(s))                    // 6: é занимает 2 байта
fmt.Println(utf8.RuneCountInString(s)) // 5
fmt.Println(s[0], string(s[0]))        // 104 h

for i, r := range s {
    fmt.Print(i, ":", string(r), " ")  // 0:h 1:é 3:l 4:l 5:o
}

b := []byte(s)   // копия, её можно менять
b[0] = 'H'
// s[0] = 'H'    // ошибка компиляции: строки неизменяемы
```

> `string(65)` даёт `"A"`, а не `"65"`, и `go vet` на это предупреждает. Для числа в строку используют `strconv.Itoa`, для руны — явный `string(rune(x))`.

## Области видимости и затенение

Каждый блок `{}`, а также заголовки `if`, `for` и `switch` создают новую область видимости. `:=` внутри неё объявляет **новую** переменную и затеняет внешнюю.

```go
x := 1
if x := 2; x > 1 {
    x++              // меняется внутренняя x
}
fmt.Println(x)       // 1

// С Go 1.22 переменная цикла своя на каждой итерации
for i := 0; i < 3; i++ {
    defer func() { fmt.Print(i) }()   // 210, до 1.22 было 333
}
for i := range 3 { fmt.Print(i) }     // 012 — range по числу, Go 1.22+
```

Частая ловушка — `err` затеняется во вложенном блоке, и внешняя переменная остаётся `nil`. Такие места находят линтеры, например анализатор `shadow` в составе golangci-lint.

## Пакеты, экспорт и инициализация

Видимость определяется первой буквой имени: `Name` экспортируется из пакета, `name` — нет. Порядок инициализации такой: сначала импортированные пакеты (каждый один раз), затем переменные уровня пакета в порядке зависимостей, затем все функции `init()` в порядке появления, и только потом `main()`.

```go
package config

var Default = load()          // 1: переменные пакета

func init() { validate() }    // 2: init, их может быть несколько

func load() *Config { ... }
```

## switch

`case` не проваливается в следующий, поэтому `break` не нужен. `fallthrough` переходит в следующий `case` без проверки условия. `switch` без выражения заменяет цепочку `if-else`.

```go
switch {
case n < 0:
    fmt.Println("neg")
case n == 0:
    fmt.Println("zero")
    fallthrough
default:
    fmt.Println("done")       // для 0 напечатает zero и done
}
```

## Частые вопросы на собеседовании

- Чем `var x = 1` отличается от `x := 1`? → `:=` работает только внутри функций и может переобъявить переменную, если слева есть хотя бы одна новая.
- Почему `len("привет")` равно 12? → `len` считает байты UTF-8, а кириллица занимает по 2 байта.
- Можно ли изменить символ строки? → нет, строки неизменяемы. Нужно сконвертировать в `[]byte`/`[]rune` и собрать новую строку.
- Что выведет замыкание над переменной цикла? → с Go 1.22 каждое замыкание видит своё значение, до 1.22 все видели последнее.
- Как работает `iota`? → это счётчик строк в блоке `const`, а пустая строка повторяет предыдущее выражение.
- В каком порядке выполняются `init`? → после переменных пакета и после всех импортированных пакетов, перед `main`.

## Шпаргалка

- Нулевые значения: `0`, `false`, `""`, `nil`; строка никогда не бывает `nil`.
- `:=` — только внутри функций; на уровне пакета нужен `var`.
- Преобразования только явные: `float64(x)`.
- Нетипизированные константы точны, целочисленное деление констант даёт целое.
- `len(s)` — байты, `s[i]` — `byte`, `range s` — руны с байтовыми индексами.
- Заглавная буква — экспорт.
- `switch` без `fallthrough` не проваливается.
- Go 1.22: переменная цикла своя на итерацию, есть `range` по числу.
