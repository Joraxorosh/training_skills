В Go нет исключений: ошибки — обычные значения, которые функции возвращают явно. Для очистки ресурсов есть `defer`, для действительно аварийных ситуаций — `panic` и `recover`. На собеседовании проверяют обёртывание ошибок, `errors.Is`/`errors.As`, порядок и момент вычисления `defer`, а также ловушки с `recover`.

## Интерфейс error и идиома if err != nil

`error` — встроенный интерфейс с одним методом. Ошибку возвращают последним результатом и сразу проверяют.

```go
type error interface {
    Error() string
}

f, err := os.Open("config.json")
if err != nil {
    return fmt.Errorf("open config: %w", err)
}
defer f.Close()
```

Сообщения ошибок пишут с маленькой буквы и без точки в конце, потому что их склеивают в цепочку: `load: open config: no such file`.

## Sentinel-ошибки и собственные типы

**Sentinel** — переменная пакета, с которой сравнивают ошибку (`io.EOF`, `sql.ErrNoRows`). Каждый вызов `errors.New` создаёт новое значение, поэтому `errors.New("x") == errors.New("x")` даёт false.

```go
var ErrNotFound = errors.New("not found")

type ValidationError struct {
    Field string
    Msg   string
}

func (e *ValidationError) Error() string {
    return e.Field + ": " + e.Msg
}
```

| Подход | Когда | Проверка |
|---|---|---|
| sentinel `var ErrX` | достаточно признака | `errors.Is(err, ErrX)` |
| свой тип | нужны данные (поле, код) | `errors.As(err, &target)` |
| непрозрачная ошибка | вызывающему не важна причина | `err != nil` |

## Обёртывание: %w, errors.Is и errors.As

`fmt.Errorf` с `%w` добавляет контекст и сохраняет исходную ошибку в цепочке. `errors.Is` и `errors.As` проходят по этой цепочке через `Unwrap`.

```go
err := fmt.Errorf("load user 42: %w", ErrNotFound)
fmt.Println(err == ErrNotFound)          // false — это новый объект
fmt.Println(errors.Is(err, ErrNotFound)) // true

err = fmt.Errorf("save: %w", &ValidationError{"email", "empty"})
var ve *ValidationError
if errors.As(err, &ve) {
    fmt.Println(ve.Field)                // email
}

joined := errors.Join(ErrNotFound, io.EOF)        // Go 1.20+
fmt.Println(errors.Is(joined, io.EOF))            // true
```

С `%v` текст получится тем же, но цепочка разорвётся, и `errors.Is` уже не найдёт исходную ошибку. С Go 1.20 `fmt.Errorf` поддерживает несколько `%w`, а ошибка может реализовать `Unwrap() []error`. `errors.Unwrap` такие ошибки не разворачивает и возвращает nil.

## defer: порядок и момент вычисления

`defer` откладывает вызов до выхода из **функции** (не блока): по `return` или при панике. Отложенные вызовы выполняются в порядке LIFO, а их **аргументы вычисляются сразу**.

```go
for i := 0; i < 3; i++ {
    defer fmt.Print(i)      // напечатает 210
}

x := 1
defer fmt.Println("arg:", x)          // arg: 1 — значение зафиксировано
defer func() { fmt.Println("closure:", x) }()  // closure: 2 — читается позже
x = 2
```

Отложенная функция может изменить **именованный** результат, потому что `return v` сначала присваивает результат, затем выполняет `defer` и только потом возвращает значение.

```go
func f() (n int) {
    defer func() { n *= 2 }()
    return 3                // вернёт 6
}

func g() int {
    n := 3
    defer func() { n *= 2 }()
    return n                // вернёт 3: результат уже скопирован
}
```

> `defer` в цикле по файлам держит все дескрипторы открытыми до конца функции. Тело цикла выносят в отдельную функцию.

## panic и recover

`panic` раскручивает стек текущей горутины и выполняет её `defer`. Если панику никто не перехватил, программа падает с трассировкой. `recover` останавливает панику, только если его **напрямую** вызывает отложенная функция.

```go
func safe() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("recovered: %v", r)
        }
    }()
    panic("boom")
}

fmt.Println(safe())          // recovered: boom

func helper() { recover() }  // бесполезно: вызван не напрямую из defer
```

Важные ограничения:

- `recover` работает только в своей горутине. Паника в горутине без собственного `recover` уронит весь процесс;
- `os.Exit` и `log.Fatal` завершают процесс сразу, без выполнения `defer`;
- рантайм-ошибки вроде `concurrent map writes` или deadlock — это fatal error, и `recover` их не перехватывает.

## Когда panic уместен

Ожидаемые ситуации (нет файла, таймаут, неверный ввод) возвращают как `error`. `panic` оставляют для багов и нарушенных инвариантов, а также для невозможности стартовать: функции `Must*` вроде `regexp.MustCompile` или `template.Must` паникуют на этапе инициализации. HTTP-серверы обычно ставят middleware с `recover`, чтобы паника в обработчике не роняла весь сервис.

## Типичные ошибки в обработке ошибок

- **Типизированный nil**: функция с результатом `error` возвращает `var p *MyErr = nil`. Интерфейс получает тип и уже не равен `nil`, поэтому возвращать нужно буквальный `nil`;
- **Двойная обработка**: ошибку и логируют, и возвращают наверх, и в логах появляются дубли. Её нужно либо обработать, либо вернуть с контекстом;
- **Сравнение текста** `err.Error() == "not found"`: такое сравнение ломается при любом изменении сообщения. Используйте `errors.Is`/`As`;
- **Игнорирование ошибки** `_ = f.Close()` при записи: для файлов, открытых на запись, ошибка `Close` может означать потерю данных;
- **Ошибки из горутин**: их собирают через канал или `errgroup`, а не теряют внутри `go func()`.

```go
func writeFile(path string, data []byte) (err error) {
    f, err := os.Create(path)
    if err != nil {
        return err
    }
    defer func() {
        if cerr := f.Close(); cerr != nil && err == nil {
            err = cerr       // не теряем ошибку Close
        }
    }()
    _, err = f.Write(data)
    return err
}
```

## Частые вопросы на собеседовании

- Чем `%w` отличается от `%v`? → `%w` сохраняет исходную ошибку для `errors.Is`/`As`, а `%v` только копирует текст.
- Когда `errors.Is`, а когда `errors.As`? → `Is` сравнивает со значением, `As` ищет тип и извлекает его.
- Когда вычисляются аргументы `defer`? → в момент выполнения `defer`, а не при выходе.
- Как `defer` может изменить результат функции? → только если результат именованный.
- Где работает `recover`? → только в отложенной функции, которая вызывает его напрямую, и только в той же горутине.
- Выполнятся ли `defer` при `os.Exit`? → нет.

## Шпаргалка

- Ошибка — значение; возвращайте последней и проверяйте сразу.
- Sentinel → `errors.Is`, свой тип → `errors.As` (указатель на переменную).
- Обёртывание — `fmt.Errorf("ctx: %w", err)`, несколько ошибок — `errors.Join`.
- `defer`: LIFO, аргументы вычисляются сразу, срабатывает при выходе из функции.
- Именованный результат можно изменить в `defer`.
- `recover` — только напрямую в `defer`, только в своей горутине.
- `os.Exit`/`log.Fatal` пропускают `defer`.
- `panic` — для багов и `Must*` при старте.
