В Go нет классов и наследования: есть структуры, методы, встраивание и интерфейсы. Интерфейсы удовлетворяются неявно, и это сильно влияет на дизайн кода. На собеседовании проверяют выбор получателя метода, наборы методов, ловушку с nil внутри интерфейса, type switch, встраивание и основы дженериков.

## Методы: получатель-значение и получатель-указатель

Метод — это функция с получателем. Получатель-значение работает с **копией**, получатель-указатель — с оригиналом.

```go
type Counter struct{ n int }

func (c Counter) Value() int { return c.n }  // копия
func (c *Counter) Inc()      { c.n++ }      // оригинал

c := Counter{}
c.Inc()          // компилятор подставит (&c).Inc() — c адресуема
fmt.Println(c.Value())   // 1
```

Указатель выбирают, когда метод меняет состояние, структура большая или содержит `sync.Mutex`. Для единообразия все методы типа обычно делают с одним видом получателя.

## Наборы методов и реализация интерфейсов

Тип реализует интерфейс, если у него есть все методы интерфейса. Слова `implements` нет.

| Тип | Набор методов |
|---|---|
| `T` | методы с получателем `T` |
| `*T` | методы с получателями `T` и `*T` |

```go
type Speaker interface{ Speak() string }
type Dog struct{}
func (d *Dog) Speak() string { return "woof" }

var s Speaker = &Dog{}    // ок
// var s Speaker = Dog{}  // ошибка: Speak имеет получатель *Dog

var _ Speaker = (*Dog)(nil)  // проверка реализации на этапе компиляции
```

Принцип «принимайте интерфейсы, возвращайте структуры»: интерфейс объявляют маленьким, на стороне потребителя. Хорошие примеры — `io.Reader` и `io.Writer`, а `io.ReadWriter` собран из них встраиванием.

## Пустой интерфейс, type assertion и type switch

`any` — псевдоним `interface{}`. Достать из него конкретное значение можно через утверждение типа или type switch.

```go
var i any = "hi"
s := i.(string)        // "hi"
n, ok := i.(int)       // 0 false — без паники
// n := i.(int)        // panic: interface conversion

func kind(v any) string {
    switch x := v.(type) {
    case int, int64:
        return "int"
    case string:
        return "string len " + strconv.Itoa(len(x))
    case nil:
        return "nil"
    default:
        return fmt.Sprintf("%T", x)
    }
}
```

`fmt.Stringer` (`String() string`) позволяет задать формат вывода для `fmt.Println`. Сравнение двух `any` с несравнимым динамическим типом (например, слайсом) компилируется, но паникует во время выполнения.

## nil-интерфейс и интерфейс с nil-указателем

Значение интерфейса — пара **(динамический тип, значение)**. Оно равно `nil`, только если пусты обе части.

```go
type MyErr struct{}
func (*MyErr) Error() string { return "boom" }

func get() error {
    var p *MyErr = nil
    return p              // интерфейс (*MyErr, nil) — НЕ nil
}

fmt.Println(get() == nil)  // false

func getOK() error {
    return nil            // правильно: возвращать nil явно
}
```

> Это самый частый вопрос по интерфейсам. Функции, которые возвращают `error`, не должны возвращать типизированный nil-указатель.

## Встраивание и композиция

Встроенный тип передаёт внешнему свои поля и методы (promotion). Но это не наследование: виртуальных методов нет.

```go
type Base struct{ ID int }
func (Base) Name() string { return "base" }
func (b Base) Hello() string { return "hello from " + b.Name() }

type User struct {
    Base              // встраивание
    Email string
}
func (User) Name() string { return "user" }

u := User{Base: Base{ID: 1}}
fmt.Println(u.ID, u.Name())  // 1 user — User.Name затеняет Base.Name
fmt.Println(u.Hello())       // hello from base — нет динамической диспетчеризации
```

Интерфейсы тоже можно встраивать: в интерфейсы и даже в структуры (например, для частичной реализации в тестах).

## Дженерики: основы

С Go 1.18 функции и типы могут иметь тип-параметры. Ограничение (constraint) — это интерфейс, который описывает допустимые типы и операции.

```go
type Number interface {
    ~int | ~int64 | ~float64   // ~ включает типы с такой основой
}

func Sum[T Number](xs []T) T {
    var s T
    for _, x := range xs {
        s += x
    }
    return s
}

func Index[T comparable](xs []T, v T) int {
    for i, x := range xs {
        if x == v {
            return i
        }
    }
    return -1
}

type Stack[T any] struct{ items []T }
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

fmt.Println(Sum([]float64{1.5, 2}), Index([]string{"a", "b"}, "b"))  // 3.5 1
```

- `any` — никаких операций, кроме присваивания и передачи;
- `comparable` — разрешены `==` и `!=`, такой тип можно сделать ключом map;
- `cmp.Ordered` — разрешены `<` и `>`;
- тип-параметр обычно выводится из аргументов.

У методов не может быть собственных тип-параметров, есть только параметры типа-получателя.

## Частые вопросы на собеседовании

- Как тип реализует интерфейс? → неявно, просто имея все нужные методы.
- Почему `Dog{}` не реализует интерфейс, если метод на `*Dog`? → набор методов `T` не включает методы `*T`.
- Почему `err != nil`, хотя вернули nil-указатель? → интерфейс хранит тип, и пара (тип, nil) не равна nil.
- Чем встраивание отличается от наследования? → это продвижение полей и методов без виртуальной диспетчеризации.
- Зачем `~` в ограничениях? → чтобы подходили пользовательские типы с той же основой, например `type ID int`.
- Чем `comparable` отличается от `cmp.Ordered`? → первое даёт `==`, второе даёт `<` и `>`.

## Шпаргалка

- Получатель-значение — копия; получатель-указатель — оригинал.
- Наборы методов: `T` → методы на T; `*T` → методы на T и *T.
- `var _ I = (*T)(nil)` — проверка реализации на этапе компиляции.
- `v, ok := i.(T)` не паникует; `i.(T)` паникует.
- Интерфейс nil ⇔ тип и значение оба nil.
- Встраивание = композиция + promotion.
- Дженерики: `[T constraint]`, `any`, `comparable`, `cmp.Ordered`, `~int`.
