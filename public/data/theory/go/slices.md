Слайсы и map — основные коллекции Go, и именно на них строится больше всего вопросов с подвохом. Чтобы уверенно отвечать, нужно понимать, что слайс — это лишь «окно» в массив, когда `append` выделяет новую память и почему map ведёт себя как ссылка. Отдельно спрашивают про строки и эффективную сборку текста.

## Массивы и заголовок слайса

Массив `[4]int` — значение фиксированного размера, при присваивании он копируется целиком. Слайс `[]int` — это маленький **заголовок** из трёх полей: указатель на массив, длина `len` и ёмкость `cap`.

```go
arr := [4]int{1, 2, 3, 4}
s := arr[1:3]               // len 2, cap 3 (от индекса 1 до конца массива)
s[0] = 20
fmt.Println(arr)            // [1 20 3 4] — массив общий

m := make([]int, 3, 10)     // [0 0 0], len 3, cap 10
```

При передаче в функцию копируется заголовок, а массив остаётся общим. Поэтому функция может менять элементы, но не длину слайса вызывающего кода.

## append и перевыделение

`append` записывает в тот же массив, если хватает ёмкости. Иначе он выделяет новый массив (для небольших слайсов примерно вдвое больше), копирует данные и возвращает заголовок на него. Результат `append` нужно **всегда** присваивать.

```go
a := []int{1, 2, 3}         // len 3, cap 3
b := append(a, 4)           // новый массив
b[0] = 100
fmt.Println(a[0])           // 1

x := make([]int, 3, 4)
y := append(x, 1)           // пишет в x-массив[3]
z := append(x, 2)           // перезаписывает тот же элемент!
fmt.Println(y[3], z[3])     // 2 2
```

Последний пример — классическая ловушка: два `append` от одного слайса с запасом ёмкости делят хвост массива.

## Полное выражение среза и copy

`a[low:high:max]` ограничивает ёмкость значением `max - low`. Тогда следующий `append` гарантированно выделит новый массив и не затрёт чужие данные.

```go
a := []int{1, 2, 3, 4}
b := a[0:2:2]               // len 2, cap 2
b = append(b, 99)           // новый массив
fmt.Println(a)              // [1 2 3 4]

dst := make([]int, 2)
n := copy(dst, []int{1, 2, 3})
fmt.Println(n, dst)         // 2 [1 2]

clone := slices.Clone(a)    // независимая копия, Go 1.21+
```

`copy` копирует `min(len(dst), len(src))` элементов и никогда не меняет длину приёмника.

## nil-слайс и пустой слайс

| | `var s []int` | `s := []int{}` |
|---|---|---|
| `s == nil` | true | false |
| `len`, `cap` | 0, 0 | 0, 0 |
| `append`, `range` | работают | работают |
| `json.Marshal` | `null` | `[]` |

Идиоматично возвращать nil-слайс и проверять пустоту через `len(s) == 0`, а не через сравнение с `nil`.

Ещё одна ловушка: `for _, v := range items` даёт **копию** элемента. Чтобы изменить структуру внутри слайса, обращаются по индексу: `items[i].n++`.

## Map

Map — хеш-таблица. Её значение по сути указатель на внутреннюю структуру, поэтому изменения внутри функции видны снаружи. Ключ должен быть сравнимым: подойдут строки, числа, массивы и структуры из сравнимых полей, но не слайсы, map и функции.

```go
m := map[string]int{"a": 1}
v, ok := m["b"]             // 0 false — comma ok
delete(m, "zzz")            // безопасно

var nm map[string]int
fmt.Println(nm["x"], len(nm))  // 0 0 — чтение из nil map безопасно
nm["x"] = 1                 // panic: assignment to entry in nil map

type P struct{ X int }
pm := map[string]P{"p": {1}}
// pm["p"].X = 2            // ошибка: элемент map не адресуем
p := pm["p"]; p.X = 2; pm["p"] = p
```

Важно помнить:

- порядок перебора не определён и намеренно рандомизируется;
- map **не потокобезопасна**: при конкурентной записи рантайм падает с `fatal error: concurrent map writes`, и `recover` её не перехватывает. Используют `sync.Mutex`/`RWMutex` или `sync.Map`;
- взять адрес элемента `&m[k]` нельзя, потому что при росте таблицы элементы перемещаются.

## Строки и strings.Builder

Строки неизменяемы, поэтому `s += part` в цикле каждый раз копирует строку, и сложность получается квадратичной. `strings.Builder` дописывает в буфер.

```go
var sb strings.Builder
for i := 0; i < 3; i++ {
    fmt.Fprintf(&sb, "%d,", i)
}
fmt.Println(sb.String())     // 0,1,2,

parts := strings.Split("a,b,c", ",")
fmt.Println(strings.Join(parts, "-"))  // a-b-c
```

Пакеты `slices` и `maps` (Go 1.21+) избавляют от ручных циклов: `slices.Sort`, `slices.Contains`, `slices.Index`, `slices.BinarySearch`, `maps.Clone`, `maps.DeleteFunc`. С Go 1.23 есть итераторы: `slices.Sorted(maps.Keys(m))` возвращает отсортированные ключи.

## Частые вопросы на собеседовании

- Что такое слайс внутри? → структура `{ptr, len, cap}`, которая указывает на массив.
- Почему результат `append` надо присваивать? → при нехватке ёмкости возвращается заголовок на новый массив.
- Зачем третий индекс в `a[l:h:m]`? → ограничить `cap`, чтобы `append` не перезаписал общий хвост.
- Что будет при записи в nil map? → паника. Чтение и `len` при этом безопасны.
- Можно ли читать и писать в map из разных горутин? → нет, нужна синхронизация или `sync.Map`.
- Как перебрать map в стабильном порядке? → отсортировать ключи и пройти по ним.

## Шпаргалка

- Слайс = `ptr + len + cap`; подслайсы делят массив.
- `append` без перевыделения пишет в общий массив; всегда пишите `s = append(s, ...)`.
- `a[l:h:m]` → `cap = m - l`.
- `copy` копирует минимум длин.
- `range` по слайсу даёт копию элемента.
- Nil map: читать можно, писать нельзя.
- Map без порядка и без потокобезопасности; ключ должен быть сравнимым.
- Сборка строк — `strings.Builder`.
