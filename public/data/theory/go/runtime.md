Помимо синтаксиса, Go-разработчика спрашивают про экосистему: как отменять операции через `context`, как устроены планировщик и сборщик мусора, где размещаются переменные, как работают модули и как тестировать и профилировать код. Эти вопросы показывают, писал ли кандидат production-сервисы.

## context.Context

Контекст переносит через цепочку вызовов сигнал отмены, дедлайн и request-scoped значения. По соглашению его передают **первым параметром** `ctx` и не хранят в долгоживущих структурах.

```go
type Context interface {
    Deadline() (deadline time.Time, ok bool)
    Done() <-chan struct{}
    Err() error
    Value(key any) any
}

ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()            // освобождает таймер, вызывать обязательно

select {
case res := <-doWork(ctx):
    fmt.Println(res)
case <-ctx.Done():
    fmt.Println(ctx.Err()) // context deadline exceeded
}
```

| Функция | Что даёт |
|---|---|
| `Background()` | пустой корень: main, тесты, инициализация |
| `TODO()` | заглушка, когда контекст ещё не протянут |
| `WithCancel` | ручная отмена, `Err()` → `context.Canceled` |
| `WithTimeout`/`WithDeadline` | отмена по времени, `Err()` → `context.DeadlineExceeded` |
| `WithValue` | новый контекст с парой ключ-значение |

Отмена распространяется **вниз**: отмена родителя отменяет всех потомков, а отмена потомка на родителя не влияет. Контексты неизменяемы. Ключ для `WithValue` делают собственным неэкспортируемым типом (`type ctxKey struct{}`), а сам `WithValue` используют только для данных уровня запроса, например trace id или пользователя.

## Планировщик GMP и GOMAXPROCS

Планировщик рантайма отображает много горутин на немного потоков ОС:

- **G** — горутина: стек, указатель команд, состояние;
- **M** — поток ОС, который выполняет код;
- **P** — логический процессор с локальной очередью готовых G. Код выполняется, только когда M владеет P.

Число P задаёт `GOMAXPROCS`. По умолчанию это число CPU, а с Go 1.25 учитываются и cgroup-лимиты контейнера. Если у P кончились задачи, он крадёт половину очереди другого P (work stealing). Когда горутина входит в блокирующий системный вызов, P передаётся другому M. Начиная с Go 1.14, долгие циклы прерываются асинхронно (preemption), и одна горутина не может захватить P навсегда.

## Сборщик мусора и escape analysis

GC в Go — **конкурентный трёхцветный mark-sweep**, без поколений и без перемещения объектов. Разметка идёт параллельно с программой с помощью write barrier, а stop-the-world паузы короткие. Частоту сборок задаёт `GOGC`: при значении 100 следующая сборка начинается, когда куча вырастет на 100% относительно живых данных. `GOMEMLIMIT` (1.19+) задаёт мягкий лимит памяти.

Где разместить переменную, решает компилятор с помощью **escape analysis**. Если ссылка переживает функцию, переменная «убегает» в кучу. Иначе она остаётся на стеке, а это дешевле и не нагружает GC.

```go
func newInt() *int {
    x := 42
    return &x       // корректно: x уйдёт в кучу
}

// go build -gcflags=-m ./...
// ./main.go:4:2: moved to heap: x
```

Помимо возврата указателя, в кучу уводят сохранение в интерфейс, захват в замыкании, которое живёт дольше функции, и слайсы неизвестного на этапе компиляции размера.

## Модули

```go
// go.mod
module example.com/shop

go 1.22

require (
    github.com/google/uuid v1.6.0
    golang.org/x/sync v0.7.0
)

replace example.com/lib => ../lib
```

- `go.mod` описывает путь модуля, версию языка (она же включает, например, per-iteration семантику цикла) и требования;
- `go.sum` хранит хеши зависимостей для проверки целостности, и его коммитят;
- `go mod tidy` добавляет недостающие и удаляет лишние зависимости;
- `replace` подменяет модуль версией или локальным путём и действует только в главном модуле. Для нескольких локальных модулей есть `go.work`;
- версии выбираются по алгоритму MVS (minimal version selection): берётся минимальная версия, которая удовлетворяет всем требованиям.

## Тестирование, vet и pprof

Тесты лежат в файлах `*_test.go`, функции называются `TestXxx(t *testing.T)`. Идиома — табличные тесты с подтестами.

```go
func TestAbs(t *testing.T) {
    tests := []struct {
        name     string
        in, want int
    }{
        {"neg", -1, 1}, {"zero", 0, 0}, {"pos", 2, 2},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            t.Parallel()        // с Go 1.22 tt := tt не нужен
            if got := Abs(tt.in); got != tt.want {
                t.Errorf("Abs(%d) = %d, want %d", tt.in, got, tt.want)
            }
        })
    }
}

func BenchmarkAbs(b *testing.B) {
    for i := 0; i < b.N; i++ {   // b.N подбирает фреймворк
        Abs(-5)
    }
}
```

- `go test ./... -race -cover`, `go test -bench=. -benchmem`, `go test -run TestAbs/neg`;
- `t.Error` фиксирует провал и продолжает тест, `t.Fatal` останавливает его;
- `go vet` находит подозрительные места: неверный формат `Printf`, копирование мьютексов, недостижимый код;
- `pprof` снимает профили CPU, heap, goroutine, block и mutex. Профили берут через `net/http/pprof` или `go test -cpuprofile`, а смотрят в `go tool pprof -http=:8080 cpu.out`.

## Build-теги

```go
//go:build linux && amd64

package sys
```

Директива стоит до `package`, после неё обязательна пустая строка. Того же эффекта добиваются суффиксами имени файла: `_linux.go`, `_amd64.go`, `_test.go`. Собственные теги включают через `go build -tags integration`.

## Частые вопросы на собеседовании

- Зачем вызывать `cancel()`, если таймаут сработает сам? → чтобы сразу освободить таймер и ресурсы дочерних контекстов.
- Отменит ли отмена дочернего контекста родителя? → нет, отмена идёт только вниз.
- Что такое G, M и P? → горутина, поток ОС и логический процессор с очередью, число которых равно `GOMAXPROCS`.
- Как устроен GC? → конкурентный трёхцветный mark-sweep без поколений, настраивается через `GOGC` и `GOMEMLIMIT`.
- Как узнать, что переменная ушла в кучу? → `go build -gcflags=-m`.
- Чем отличаются `go.mod` и `go.sum`? → требования к зависимостям против хешей для проверки.

## Шпаргалка

- `ctx` — первый параметр; всегда `defer cancel()`.
- `Canceled` против `DeadlineExceeded`; отмена идёт вниз по дереву.
- GMP: M выполняет G, когда держит P; число P = `GOMAXPROCS`.
- GC: concurrent mark-sweep, `GOGC=100`, `GOMEMLIMIT`.
- Escape analysis: `-gcflags=-m`.
- `go mod tidy`, `replace`, `go.work`, MVS.
- Тесты: `*_test.go`, табличные, `t.Run`, `-race`, `-bench`.
- `go vet`, `pprof`, `//go:build`.
