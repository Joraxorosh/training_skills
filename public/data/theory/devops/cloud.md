Облака дают инфраструктуру по API и платёжной модели pay-as-you-go. DevOps-инженер должен понимать модели сервисов, устройство регионов и зон доступности, сетевую модель VPC, IAM, основные сервисы (на примере AWS — у GCP и Azure есть аналоги) и архитектурные принципы отказоустойчивых систем.

## Модели сервисов и ответственность

| Модель | Вы управляете | Пример |
|---|---|---|
| IaaS | ОС, рантайм, приложение | EC2, Compute Engine |
| PaaS | Приложение и данные | Heroku, Elastic Beanstalk, App Engine, Cloud Run |
| SaaS | Только данными и настройками | Gmail, Slack |
| FaaS / Serverless | Код функции | AWS Lambda, Cloud Functions |

**Shared responsibility**: провайдер отвечает за безопасность **облака** (дата-центры, железо, гипервизор, управляемые сервисы), клиент — за безопасность **в облаке** (IAM, данные, шифрование, настройки сети, патчи ОС на своих ВМ).

**Serverless**: оплата за вызовы и время выполнения, автомасштабирование до нуля, ограничения по времени выполнения (Lambda — до 15 минут), холодный старт, функции stateless.

## Регионы и зоны доступности

**Регион** — географическая область. **Availability Zone** — один или несколько изолированных дата-центров внутри региона с независимым питанием и сетью, соединённых быстрыми каналами. Отказоустойчивость строят размещением ресурсов в нескольких AZ, катастрофоустойчивость — в нескольких регионах.

## Сеть: VPC

- **Публичная подсеть** — в её таблице маршрутов есть маршрут `0.0.0.0/0` на **Internet Gateway**.
- **Приватная подсеть** — такого маршрута нет. Для исходящего доступа в интернет используют **NAT Gateway** в публичной подсети; входящие соединения из интернета невозможны.
- **VPC Endpoint** (Gateway endpoint для S3 и DynamoDB бесплатен) позволяет ходить в сервисы AWS без NAT, что резко снижает стоимость трафика.
- **VPC Peering** не транзитивен: A↔B и B↔C не дают A↔C. Для хабовой топологии — Transit Gateway.

| | Security Group | Network ACL |
|---|---|---|
| Уровень | Сетевой интерфейс (инстанс) | Подсеть |
| Состояние | **Stateful**: ответный трафик разрешён автоматически | **Stateless**: правила для обоих направлений |
| Правила | Только allow | Allow и deny, по номерам по порядку |

## IAM и принцип наименьших привилегий

**Least privilege** — каждому субъекту ровно те права, которые нужны для задачи, и не больше. Используют роли с временными учётными данными вместо постоянных ключей, MFA, отдельные аккаунты для окружений.

Логика оценки политик AWS: по умолчанию всё запрещено (implicit deny), `Allow` разрешает, а **явный `Deny` всегда побеждает** любой Allow.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "s3:*", "Resource": "arn:aws:s3:::data/*" },
    { "Effect": "Deny", "Action": "s3:DeleteObject", "Resource": "arn:aws:s3:::data/*" }
  ]
}
```

Здесь удаление объекта будет запрещено, несмотря на `s3:*`.

## Вычисления, хранение, базы и балансировщики

- **EC2** — ВМ. Типы покупки: On-Demand, Reserved/Savings Plans (скидка за обязательства), **Spot** — до 90% дешевле, но могут быть отозваны с предупреждением за 2 минуты; подходят для прерываемых, stateless, batch-задач, CI-раннеров.
- **Auto Scaling Group** с target tracking (например, средний CPU 50%) сама добавляет инстансы, когда метрика выше цели, и убирает, когда ниже.
- **S3** — объектное хранилище: бакеты и объекты, практически неограниченный объём, 11 девяток долговечности, строгая read-after-write консистентность, версионирование, lifecycle-политики и классы хранения (Standard, IA, Glacier). Это не файловая система и не блочное устройство (для этого EBS и EFS).
- **RDS** — управляемая реляционная БД: провайдер делает патчи, бэкапы, point-in-time recovery, Multi-AZ с синхронной репликой и автоматическим failover; read replicas — асинхронные, для масштабирования чтения. Доступа к ОС нет.

| Балансировщик | Уровень | Особенности |
|---|---|---|
| ALB | L7 (HTTP/HTTPS, gRPC) | Маршрутизация по пути, Host, заголовкам |
| NLB | L4 (TCP/UDP/TLS) | Минимальная задержка, статический IP, сохраняет IP клиента |
| GWLB | L3 | Для виртуальных сетевых устройств |

## Архитектурные принципы

- **Горизонтальное масштабирование** — добавление экземпляров (scale out), вертикальное — увеличение мощности одного (scale up).
- **Stateless-сервисы** проще масштабировать: любой экземпляр может обработать любой запрос, а состояние (сессии, файлы) вынесено в БД, Redis, S3.
- **CAP-теорема**: при сетевом разделении (P) распределённая система должна выбрать между согласованностью (C) и доступностью (A).
- **Circuit Breaker**: при серии ошибок зависимости прекращает к ней обращения на время, быстро возвращая ошибку или fallback, — предотвращает каскадные отказы. Рядом: retries с exponential backoff и jitter, timeouts, bulkhead.
- **RPO** — допустимая потеря данных во времени (бэкап раз в 24 часа → RPO до 24 часов). **RTO** — допустимое время восстановления (восстановление 4 часа → RTO не меньше 4 часов).

## Частые вопросы на собеседовании

- Что такое AZ? → Изолированный дата-центр (или группа) в регионе с независимой инфраструктурой.
- SG vs NACL? → SG stateful на инстансе, только allow; NACL stateless на подсети, allow и deny.
- Как дать приватной подсети выход в интернет? → NAT Gateway в публичной подсети + маршрут.
- Почему S3 через NAT дорого? → Оплата за трафик NAT; решение — Gateway VPC Endpoint.
- Peering A-B, B-C — есть ли A-C? → Нет, peering не транзитивен.
- RPO vs RTO? → Сколько данных можем потерять vs как долго можем лежать.

## Шпаргалка

- IaaS / PaaS / SaaS / FaaS; shared responsibility
- Region → AZ; Multi-AZ для HA, Multi-region для DR
- Public subnet = маршрут на IGW; private + NAT GW; VPC Endpoint для S3
- SG stateful, NACL stateless; explicit Deny побеждает
- ALB = L7, NLB = L4 (TCP/UDP)
- Spot — для прерываемых задач; ASG target tracking
- Stateless, scale out, circuit breaker, retries + backoff
- RPO = потеря данных, RTO = время простоя
