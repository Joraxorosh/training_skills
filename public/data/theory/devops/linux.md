Linux — основная ОС серверов, контейнеров и CI-раннеров, а Bash — язык, на котором DevOps-инженер общается с ней каждый день. На собеседовании проверяют не знание всех флагов, а понимание модели: файлы и права, процессы и сигналы, потоки ввода-вывода, systemd и диагностику «почему тормозит / закончилось место».

## Файлы, права и ссылки

Права задаются для трёх групп: владелец (u), группа (g), остальные (o). Каждая тройка — r=4, w=2, x=1. `chmod 750 file` даёт `rwxr-x---`. Для каталога `x` означает право входить в него, `r` — читать список файлов.

```bash
pwd                      # абсолютный путь текущего каталога
chmod 644 app.conf       # rw-r--r--
chmod u+x deploy.sh      # добавить исполнение владельцу
chown app:app /srv/app   # сменить владельца и группу
umask                    # маска прав по умолчанию (обычно 022)
setfacl -m u:bob:rw file # POSIX ACL: точечные права сверх ugo
getfacl file
```

Метаданные файла хранятся в **inode**: тип, права, владелец, размер, временные метки, счётчик ссылок, указатели на блоки данных. **Имя файла в inode не хранится** — оно лежит в записи каталога.

| | Жёсткая ссылка (ln) | Символьная ссылка (ln -s) |
|---|---|---|
| Что это | Ещё одно имя того же inode | Отдельный файл с путём к цели |
| Между ФС | Нельзя | Можно |
| На каталог | Нельзя | Можно |
| После удаления оригинала | Данные доступны | Ссылка «битая» |

## Процессы и сигналы

У каждого процесса есть PID, родитель (PPID), состояние. **Зомби** — процесс, который завершился, но родитель ещё не прочитал его код возврата через `wait()`. Зомби не потребляет CPU и память, только запись в таблице процессов; убить его `kill` нельзя — нужно, чтобы родитель вызвал wait или сам завершился (тогда зомби усыновит init и уберёт).

| Сигнал | Номер | Смысл |
|---|---|---|
| SIGTERM | 15 | Вежливая просьба завершиться (по умолчанию у `kill`) |
| SIGKILL | 9 | Немедленное убийство, перехватить нельзя |
| SIGINT | 2 | Ctrl+C |
| SIGHUP | 1 | Обрыв терминала / часто «перечитай конфиг» |
| SIGTSTP | 20 | Ctrl+Z, приостановка |

```bash
ps aux | grep nginx
kill 1234          # SIGTERM
kill -9 1234       # SIGKILL
jobs; bg %1; fg %1 # после Ctrl+Z: продолжить в фоне / на переднем плане
uptime             # load average за 1, 5 и 15 минут
```

**Load average** — среднее число процессов в состоянии running/runnable плюс в непрерываемом ожидании (D, обычно I/O) за 1, 5 и 15 минут. Сравнивают с числом ядер.

## Потоки, перенаправления и Bash

Дескрипторы: 0 — stdin, 1 — stdout, 2 — stderr. `cmd > out.log 2>&1` отправляет и stdout, и stderr в файл (порядок важен: сначала stdout в файл, затем stderr туда же, куда stdout).

```bash
echo $?                 # код возврата последней команды: 0 — успех
cmd1 && cmd2            # cmd2 только при успехе cmd1
cmd1 || cmd2            # cmd2 только при ошибке cmd1
set -euo pipefail       # строгий режим скриптов
name="world"; echo "Hello, ${name}"   # двойные кавычки раскрывают переменные
echo 'Hello, ${name}'                 # одинарные — нет
```

> Частая ловушка: без `set -o pipefail` код возврата пайплайна равен коду последней команды, ошибки в середине теряются. А переменные, изменённые внутри `while ... done` в правой части пайпа, в bash по умолчанию живут в подоболочке и «пропадают» после цикла.

## Поиск и обработка текста

```bash
find / -type f -size +100M 2>/dev/null   # файлы больше 100 МБ
grep -r "ERROR" /var/log/app/            # рекурсивный поиск
grep -v "DEBUG" app.log                  # строки, НЕ совпадающие с шаблоном
grep -i / -c / -n                        # без регистра / подсчёт / номера строк
tail -f app.log    # или tail -F (переоткрывает файл при ротации), less +F
sed -i 's/old/new/g' config.ini          # замена на месте во всех вхождениях
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
```

## systemd, журналы и cron

```bash
systemctl enable --now nginx     # автозагрузка + запуск сразу
systemctl status nginx
systemctl restart / reload nginx
journalctl -u nginx.service -f   # логи юнита, follow
journalctl --since "1 hour ago"
```

Формат crontab: `минута час день_месяца месяц день_недели команда`. Пример: `*/15 9-18 * * 1-5 /opt/backup.sh` — каждые 15 минут с 9 до 18 часов по будням.

## Диски и ресурсы

`df -h` показывает заполненность файловых систем, `du -sh *` — размер каталогов. Если **df показывает 100%, а du — намного меньше**, почти всегда виноват удалённый, но всё ещё открытый процессом файл (например, ротированный лог). Найти: `lsof +L1` или `lsof | grep deleted`; решение — перезапустить процесс или очистить файл через `/proc/PID/fd/N`. Ещё одна причина «места нет, а df показывает свободно» — закончились inode (`df -i`).

## Namespaces и cgroups

Это основа контейнеров. **Namespaces** изолируют то, что процесс видит: pid, net, mnt, uts, ipc, user, cgroup. **cgroups** ограничивают и учитывают ресурсы: CPU, память, I/O, число процессов. В современных дистрибутивах используется cgroup v2 (единая иерархия). Namespaces — про видимость, cgroups — про лимиты.

## Частые вопросы на собеседовании

- Чем SIGTERM отличается от SIGKILL? → TERM можно перехватить и корректно завершиться, KILL — нет.
- Что такое зомби-процесс? → Завершившийся процесс, код возврата которого не забрал родитель; лечится через родителя.
- df 100%, du мало — почему? → Удалённый, но открытый файл; ищем `lsof +L1`.
- Что значит `2>&1`? → Перенаправить stderr туда же, куда сейчас указывает stdout.
- Что не хранится в inode? → Имя файла.
- Hard link vs symlink? → Hard — второе имя inode в той же ФС; symlink — файл-указатель на путь.
