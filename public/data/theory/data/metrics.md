Продуктовые метрики переводят поведение пользователей в числа, по которым принимают решения: растёт ли аудитория, возвращаются ли люди, окупается ли привлечение. На собеседовании продуктового аналитика проверяют определения, умение правильно выбрать знаменатель и разложить метрику на составляющие, когда она «упала».

## Активность: DAU, WAU, MAU и stickiness

- **DAU / WAU / MAU** — число уникальных активных пользователей за день, неделю, 30 дней. Что считать «активностью», нужно определить явно: открытие приложения, ключевое действие, платёж.
- **Stickiness** = `DAU / MAU` — регулярность использования. 0.25 означает, что средний месячный пользователь активен около 7–8 дней из 30.

MAU нельзя получить суммой DAU: человек, заходивший 20 дней, будет посчитан 20 раз. Уникальность считается на всём периоде.

```python
dau = events.groupby(events.ts.dt.date)['user_id'].nunique()
mau = events[events.ts >= '2024-03-01']['user_id'].nunique()
```

## Удержание и отток

**Retention дня N (классический)** — доля когорты, активной именно в день N. **Rolling (unbounded) retention** — доля активных в день N или позже (по дате последней активности); он всегда не меньше классического и монотонно не растёт.

**Churn rate** = ушедшие за период / клиенты на начало периода. Для подписок это отмена; для бесплатных продуктов «уход» определяют через неактивность (например, 30 дней без визитов).

**Когортный анализ** группирует пользователей по дате первого действия и следит за каждой когортой отдельно:

```python
first = ev.groupby('user')['date'].transform('min')
ev['cohort'] = first.dt.to_period('M')
ev['age'] = (ev['date'].dt.to_period('M') - ev['cohort']).apply(lambda d: d.n)
table = ev.pivot_table(index='cohort', columns='age',
                       values='user', aggfunc='nunique')
retention = table.div(table[0], axis=0)
```

| Когорта | Месяц 0 | Месяц 1 | Месяц 2 |
|---|---|---|---|
| 2024-01 | 100% | 42% | 31% |
| 2024-02 | 100% | 39% | 28% |

> Агрегированный retention может расти, пока каждая когорта ухудшается: если новых пользователей приходит меньше, в общей массе преобладают лояльные старожилы. Это парадокс Симпсона, поэтому смотрят по когортам.

## Воронки и конверсия

Воронка — последовательность шагов: визит → карточка → корзина → оплата. Считают пошаговую конверсию и сквозную.

| Шаг | Пользователи | Конверсия шага |
|---|---|---|
| Визит | 10 000 | — |
| Карточка | 4 000 | 40% |
| Корзина | 1 000 | 25% |
| Оплата | 800 | 80% |

Узкое место — шаг с наименьшей конверсией (карточка → корзина). Сравнивая воронки между периодами, проверяйте микс трафика, изменения логирования и сезонность.

## Деньги: ARPU, LTV, CAC, payback

- **ARPU** = выручка / все активные пользователи; **ARPPU** = выручка / платящие. `ARPU = ARPPU × конверсия в оплату`.
- **LTV** — суммарная маржа с клиента за время жизни. Простая оценка для подписки: `LTV = ARPU × маржа / churn`.
- **CAC** = расходы на привлечение / новые клиенты.
- **Payback period** = CAC / ежемесячная маржа с клиента.

```python
arpu, margin, churn = 300, 0.4, 0.1
ltv = arpu * margin / churn     # 1200 ₽: 10 месяцев жизни × 120 ₽
payback = 3000 / 500            # 6 месяцев при CAC 3000 и марже 500
```

Ориентир здоровой юнит-экономики — `LTV / CAC ≥ 3` и окупаемость меньше срока жизни клиента. LTV считают по марже, а не по выручке. **Blended CAC** включает органику и занижает стоимость платных каналов; для решений о бюджете смотрят paid CAC по каналам и его рост при масштабировании.

**Юнит-экономика** считает прибыль на единицу — клиента или заказ: `чек − себестоимость − доставка − комиссии`. Если маржа на единицу отрицательна, рост объёма увеличивает убытки.

## North Star, guardrail и дерево метрик

**North Star Metric** — одна метрика, отражающая ценность для пользователя и предсказывающая будущую выручку: минуты прослушивания, завершённые поездки, недельно активные команды. На неё должны влиять продуктовые команды.

**Guardrail-метрики** не должны ухудшиться при оптимизации целевой: скорость загрузки, отписки, жалобы, retention.

**Дерево метрик** раскладывает верхнюю метрику на множители:

```text
Выручка = Активные пользователи × Конверсия в покупку × Средний чек
Активные = Новые + Вернувшиеся
```

Когда выручка упала, дерево показывает, какой компонент изменился, и куда копать дальше. Каждая ветка закрепляется за командой.

## Частые вопросы на собеседовании

- Почему MAU ≠ сумма DAU? → Повторные пользователи учитываются многократно.
- Чем rolling retention отличается от классического? → Учитывает возврат в день N или позже, поэтому выше.
- Как посчитать LTV? → Маржа с клиента за срок жизни; просто — `ARPU × маржа / churn`.
- Что делать, если выручка упала на 10%? → Проверить данные, разложить по дереву метрик, сегментам и каналам.
- Чем ARPU отличается от ARPPU? → Знаменатель: все пользователи против платящих.
- Что такое guardrail-метрика? → Метрика, которая не должна ухудшиться в эксперименте.

## Шпаргалка

| Метрика | Формула |
|---|---|
| Stickiness | `DAU / MAU` |
| Churn | Ушедшие / клиенты на начало |
| Retention N | Активные в день N / размер когорты |
| ARPU | Выручка / активные |
| ARPPU | Выручка / платящие |
| LTV | `ARPU × маржа / churn` |
| CAC | Маркетинг / новые клиенты |
| Payback | `CAC / маржа в месяц` |
| Здоровая экономика | `LTV / CAC ≥ 3` |
| Конверсия шага | Шаг k / шаг k−1 |
