Рекурсия, жадные алгоритмы и динамическое программирование — три способа разбить задачу на подзадачи. Рекурсия решает задачу через её же меньшие копии, жадный алгоритм на каждом шаге делает локально лучший выбор, а динамическое программирование (DP) запоминает ответы перекрывающихся подзадач. DP считается самой сложной темой собеседований, но в её основе лежит понятный рецепт, который мы и разберём.

## Рекурсия

Рекурсивная функция содержит **базовый случай** (ответ известен сразу) и **рекурсивный шаг**, который приближает к базовому. Каждый вызов занимает кадр стека, поэтому память — O(глубина). В Python лимит глубины по умолчанию 1000, а оптимизации хвостовой рекурсии нет.

```python
def power(x, n):                   # быстрое возведение в степень, O(log n)
    if n == 0:
        return 1
    half = power(x, n // 2)
    return half * half * (x if n % 2 else 1)

print(power(2, 30))                # 1073741824
```

> Забытый или недостижимый базовый случай даёт `RecursionError`. Глубокую рекурсию (например, по связному списку из 10⁵ узлов) лучше переписать итеративно с явным стеком.

## От рекурсии к DP: мемоизация и табуляция

DP применимо, когда у задачи есть:

1. **Оптимальная подструктура** — оптимальный ответ собирается из оптимальных ответов подзадач.
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи решаются многократно.

Наивный Фибоначчи вызывает `fib(n-2)` дважды, `fib(n-3)` трижды и так далее — O(2ⁿ). Запомнив результаты, получаем O(n).

| | Мемоизация (top-down) | Табуляция (bottom-up) |
|---|---|---|
| Как | рекурсия + кэш | цикл по таблице от малых к большим |
| Вычисляет | только нужные подзадачи | все подзадачи |
| Стек | O(глубина), риск `RecursionError` | не нужен |
| Оптимизация памяти | сложно | легко хранить только последние строки |
| Писать | проще из рекурсивной формулы | нужно продумать порядок |

```python
from functools import cache

@cache
def fib_memo(n):
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

def fib_tab(n):
    a, b = 0, 1                    # память O(1): храним только два значения
    for _ in range(n):
        a, b = b, a + b
    return a

print(fib_memo(50), fib_tab(50))   # 12586269025 12586269025
```

**Рецепт решения DP-задачи:**

1. Определите состояние: что означает `dp[i]` (или `dp[i][j]`).
2. Запишите переход: как `dp[i]` выражается через меньшие состояния.
3. Задайте базовые случаи.
4. Определите порядок вычисления и где лежит ответ.
5. Оцените сложность: число состояний × стоимость перехода. Оптимизируйте память.

## Классические задачи

| Задача | Состояние | Переход | Сложность |
|---|---|---|---|
| Лестница (1 или 2 шага) | `dp[i]` — способов дойти до i | `dp[i-1] + dp[i-2]` | O(n) |
| Размен монет (минимум) | `dp[s]` — монет на сумму s | `min(dp[s-c] + 1)` | O(S * k) |
| Рюкзак 0/1 | `dp[w]` — макс. ценность при весе w | `max(dp[w], dp[w-wi] + vi)` | O(n * W) |
| НВП (LIS) | `dp[i]` — длина НВП, кончающейся в i | `max(dp[j] + 1)`, j < i | O(n²), O(n log n) |
| НОП (LCS) | `dp[i][j]` — для префиксов | равны: `+1`, иначе max | O(n * m) |
| Расстояние Левенштейна | `dp[i][j]` — правок для префиксов | `1 + min(трёх соседей)` | O(n * m) |
| Грабитель домов | `dp[i]` — максимум до i | `max(dp[i-1], dp[i-2] + a[i])` | O(n) |

```python
def coin_change(coins, amount):
    INF = float("inf")
    dp = [0] + [INF] * amount
    for s in range(1, amount + 1):
        for c in coins:
            if c <= s:
                dp[s] = min(dp[s], dp[s - c] + 1)
    return dp[amount] if dp[amount] != INF else -1

def knapsack(items, cap):          # items: (вес, ценность)
    dp = [0] * (cap + 1)
    for w, v in items:
        for c in range(cap, w - 1, -1):   # обратный порядок: каждый предмет один раз
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]

def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(coin_change([1, 3, 4], 6))                   # 2  (3 + 3)
print(knapsack([(1, 1), (3, 4), (4, 5), (5, 7)], 7))   # 9
print(lcs("abcde", "ace"))                         # 3
```

## Жадные алгоритмы

Жадный алгоритм на каждом шаге выбирает локально оптимальный вариант и никогда не пересматривает решение. Он работает, если у задачи есть **свойство жадного выбора** — локально лучший шаг всегда входит в какое-то оптимальное решение. Это нужно доказать (обычно аргументом обмена), иначе жадность легко ошибается.

Где жадность верна: выбор максимального числа непересекающихся интервалов (сортируем по **концу**), алгоритмы Дейкстры, Краскала и Прима, кодирование Хаффмана, «прыжки по массиву», непрерывный рюкзак (по ценности на единицу веса).

```python
def max_meetings(intervals):
    count, end = 0, float("-inf")
    for s, e in sorted(intervals, key=lambda x: x[1]):
        if s >= end:
            count, end = count + 1, e
    return count

def greedy_coins(coins, amount):
    count = 0
    for c in sorted(coins, reverse=True):
        count += amount // c
        amount %= c
    return count if amount == 0 else -1

print(max_meetings([(1, 4), (3, 5), (0, 6), (5, 7), (8, 9)]))   # 3
print(greedy_coins([1, 3, 4], 6), coin_change([1, 3, 4], 6))    # 3 2
```

> Классический контрпример: монеты `[1, 3, 4]` и сумма 6. Жадность берёт 4 + 1 + 1 (три монеты), а оптимум — 3 + 3. Жадный размен корректен только для «канонических» систем вроде `[1, 5, 10, 25]`. Аналогично жадность не решает рюкзак 0/1.

## Перебор с возвратом (backtracking)

Backtracking строит решение по шагам и откатывает последний выбор, если путь не ведёт к ответу. Шаблон: выбрать → рекурсия → отменить выбор. Отсечения (pruning) обрезают заведомо бесполезные ветви. Сложность экспоненциальная, но это единственный путь для задач «найти все»: подмножества, перестановки, N ферзей, судоку, комбинации с суммой.

```python
def subsets(nums):
    res, path = [], []
    def go(i):
        if i == len(nums):
            res.append(path[:])            # копия!
            return
        path.append(nums[i]); go(i + 1)    # взять
        path.pop(); go(i + 1)              # не брать
    go(0)
    return res

def permutations(nums):
    res = []
    def go(path, used):
        if len(path) == len(nums):
            res.append(path[:]); return
        for i, x in enumerate(nums):
            if not used[i]:
                used[i] = True; path.append(x)
                go(path, used)
                path.pop(); used[i] = False
    go([], [False] * len(nums))
    return res

print(subsets([1, 2]))             # [[1, 2], [1], [2], []]
print(len(permutations([1, 2, 3])))   # 6
```

## Частые вопросы на собеседовании

- Когда применимо DP? → есть оптимальная подструктура и перекрывающиеся подзадачи.
- Мемоизация или табуляция? → мемоизация проще писать, табуляция без риска переполнения стека и легче экономит память.
- Почему в рюкзаке 0/1 вес перебирается в обратном порядке? → чтобы каждый предмет использовался не больше одного раза.
- Когда жадный алгоритм не работает? → когда локально лучший выбор не ведёт к глобальному оптимуму; монеты `[1, 3, 4]`, рюкзак 0/1.
- Чем backtracking отличается от DP? → перебирает все варианты с откатом; DP переиспользует ответы подзадач.
- Как оценить сложность DP? → число состояний × стоимость одного перехода.

## Шпаргалка

- Рекурсия: базовый случай + шаг; память O(глубина); лимит 1000.
- DP = рекурсия + запоминание; `@cache` — самый быстрый путь к мемоизации.
- Рецепт: состояние → переход → база → порядок → ответ.
- Часто достаточно хранить последнюю строку таблицы.
- Жадность требует доказательства; интервалы — сортировка по концу.
- Backtracking: выбрать → рекурсия → отменить; добавлять копию `path[:]`.
