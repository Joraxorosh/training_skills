Задачи на массивы и строки — самые частые на алгоритмических собеседованиях. Почти все они решаются небольшим набором приёмов: два указателя, скользящее окно, префиксные суммы и хеш-таблица. Цель обычно одна — превратить наивное решение O(n²) в O(n). Научившись узнавать паттерн по формулировке, вы решите большинство задач уровня easy и medium.

## Массивы и строки: базовые факты

| Операция | Массив (`list`) | Строка (`str`) |
|---|---|---|
| Доступ по индексу | O(1) | O(1) |
| Добавление в конец | O(1) амортизированно | создаёт новую строку, O(n) |
| Вставка/удаление в середине | O(n) | O(n), новая строка |
| Поиск значения | O(n) | O(n) |
| Срез длины k | O(k) | O(k) |

Строки в Python неизменяемы: `s += c` в цикле может стоить O(n²). Собирайте части в список и делайте `"".join(parts)`.

## Два указателя

Два индекса движутся навстречу друг другу или в одном направлении с разной скоростью. Работает на **отсортированных** массивах и для задач «на месте».

```python
def pair_sum_sorted(nums, target):       # O(n), O(1) памяти
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        s = nums[lo] + nums[hi]
        if s == target:
            return lo, hi
        if s < target:
            lo += 1
        else:
            hi -= 1
    return None

def is_palindrome(s):
    s = [c.lower() for c in s if c.isalnum()]
    return s == s[::-1]

def remove_duplicates(nums):             # отсортированный массив, на месте
    w = 0
    for r in range(len(nums)):
        if r == 0 or nums[r] != nums[r - 1]:
            nums[w] = nums[r]
            w += 1
    return w

print(pair_sum_sorted([1, 3, 4, 6, 9], 10))      # (0, 4)
print(is_palindrome("A man, a plan, a canal: Panama"))   # True
arr = [1, 1, 2, 3, 3]
print(remove_duplicates(arr), arr[:3])           # 3 [1, 2, 3]
```

## Скользящее окно

Окно `[left, right]` расширяется правым краем и сужается левым. Подходит для задач про **непрерывный подмассив или подстроку**: максимальная сумма длины k, самая длинная подстрока без повторов, минимальное окно с условием. Каждый элемент входит и выходит из окна по разу — итого O(n).

```python
def max_sum_k(nums, k):                  # окно фиксированного размера
    window = best = sum(nums[:k])
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best

def longest_unique(s):                   # окно переменного размера
    last = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in last and last[ch] >= left:
            left = last[ch] + 1
        last[ch] = right
        best = max(best, right - left + 1)
    return best

print(max_sum_k([2, 1, 5, 1, 3, 2], 3))  # 9
print(longest_unique("abcabcbb"))         # 3
```

## Префиксные суммы

`prefix[i]` — сумма первых i элементов. Сумма любого отрезка `[l, r)` считается за O(1): `prefix[r] - prefix[l]`. Вместе с хеш-таблицей решает задачу «количество подмассивов с суммой k» даже с отрицательными числами, где окно не работает.

```python
from itertools import accumulate
from collections import defaultdict

nums = [3, 1, 4, 1, 5]
prefix = [0, *accumulate(nums)]
print(prefix, prefix[4] - prefix[1])     # [0, 3, 4, 8, 9, 14] 6

def count_subarrays(nums, k):            # O(n)
    seen = defaultdict(int)
    seen[0] = 1
    total = count = 0
    for x in nums:
        total += x
        count += seen[total - k]
        seen[total] += 1
    return count

print(count_subarrays([1, 2, 1, -1, 2], 3))   # 3
```

## Хеш-таблицы

Хеш-таблица хранит пары ключ–значение в массиве «корзин». Индекс вычисляется из хеша ключа: `hash(key) % capacity`. Операции в среднем O(1), в худшем O(n).

- **Коллизия** — разные ключи попали в одну корзину. Решения: **цепочки** (в корзине список пар, как в Java `HashMap`) или **открытая адресация** (ищем следующую свободную ячейку по схеме пробирования — так устроены `dict` и `set` в CPython).
- **Коэффициент заполнения** (load factor) = элементов / ёмкость. Когда он превышает порог (около 2/3 в CPython, 0.75 в Java), таблица увеличивается и все элементы перехешируются — O(n), но редко, поэтому вставка остаётся O(1) амортизированно.
- Худший случай O(n) — при плохой хеш-функции или атаке на коллизии; поэтому в Python хеш строк рандомизирован (`PYTHONHASHSEED`).

| Задача | Что хранить в хеше |
|---|---|
| Two Sum | значение → индекс |
| Анаграммы | отсортированная строка или `Counter` → группа |
| Первый уникальный символ | символ → количество |
| Подмассив с суммой k | префиксная сумма → количество |
| Найти дубликат | множество просмотренных |

```python
def two_sum(nums, target):
    index = {}
    for i, x in enumerate(nums):
        if target - x in index:
            return index[target - x], i
        index[x] = i

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())

print(two_sum([2, 7, 11, 15], 9))                # (0, 1)
print(group_anagrams(["eat", "tea", "tan", "ate", "nat"]))
# [['eat', 'tea', 'ate'], ['tan', 'nat']]
```

## Как узнать паттерн

| Признак в условии | Приём |
|---|---|
| массив отсортирован, пара/тройка с суммой | два указателя |
| «непрерывный подмассив/подстрока», максимум/минимум длины | скользящее окно |
| много запросов суммы на отрезке | префиксные суммы |
| «найти, встречалось ли», подсчёт, группировка | хеш-таблица |
| подмассив с суммой k и отрицательные числа | префиксы + хеш |
| ответ на месте с O(1) памяти | два указателя, запись по индексу |

> Перед кодом проговорите наивное решение и его сложность, затем назовите паттерн и улучшенную сложность. Интервьюер оценивает ход мысли не меньше, чем код. И не забудьте граничные случаи: пустой массив, один элемент, все одинаковые, отрицательные числа.

## Частые вопросы на собеседовании

- Как найти пару с суммой за O(n)? → хеш-множество просмотренных или два указателя на отсортированном массиве.
- Почему скользящее окно — O(n), хотя там вложенный цикл? → каждый индекс сдвигается только вперёд, суммарно не больше 2n шагов.
- Что такое коллизия и как её решают? → совпадение корзин; цепочки или открытая адресация.
- Почему вставка в хеш-таблицу O(1), если бывает рехеширование? → оно редкое, амортизированная стоимость O(1).
- Когда окно не работает для «подмассива с суммой k»? → при отрицательных числах; нужны префиксные суммы с хешем.

## Шпаргалка

- Строки собирать через `"".join`, не `+=` в цикле.
- Два указателя — отсортированные данные и работа на месте.
- Окно — непрерывные подотрезки; расширяем справа, сужаем слева.
- `sum(l..r) = prefix[r+1] - prefix[l]`.
- Хеш-таблица: O(1) в среднем, O(n) в худшем; рехеширование при load factor выше порога.
- `index[value] = i` — классика Two Sum.
- Сначала наивное решение, потом оптимизация и граничные случаи.
