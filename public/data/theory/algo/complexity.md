Асимптотическая сложность — язык, на котором обсуждают алгоритмы. Она описывает, как растут время работы и потребление памяти при росте размера входа `n`, отбрасывая константы и детали железа. На любом алгоритмическом собеседовании после решения задачи вас спросят: «Какая сложность по времени и по памяти?» — и ответ должен быть быстрым и обоснованным.

## O, Ω и Θ

- **O(f(n))** — верхняя граница: алгоритм растёт **не быстрее** f(n) (с точностью до константы, для больших n).
- **Ω(f(n))** — нижняя граница: растёт **не медленнее** f(n).
- **Θ(f(n))** — точная оценка: одновременно O и Ω.

Формально `g(n) = O(f(n))`, если существуют `c > 0` и `n0`, что `g(n) <= c * f(n)` для всех `n >= n0`. На практике под «O» почти всегда подразумевают точную оценку худшего случая.

Не путайте границы и случаи: лучший, средний и худший случай — это разные входы, и для каждого можно дать свою оценку. Quicksort: в среднем Θ(n log n), в худшем Θ(n²).

## Правила подсчёта

1. Константы отбрасываются: `O(3n + 5) = O(n)`.
2. Младшие слагаемые отбрасываются: `O(n² + n log n) = O(n²)`.
3. Последовательные блоки складываются: `O(n) + O(m) = O(n + m)`.
4. Вложенные циклы перемножаются: цикл по n внутри цикла по m — `O(n * m)`.
5. Разные входы — разные переменные: не сводите `O(n + m)` к `O(n)`.
6. Основание логарифма не важно: `log2 n` и `log10 n` отличаются константой.

```python
def has_pair_sum(nums, target):     # O(n²) время, O(1) память
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return True
    return False

def has_pair_sum_fast(nums, target):  # O(n) время, O(n) память
    seen = set()
    for x in nums:
        if target - x in seen:
            return True
        seen.add(x)
    return False

print(has_pair_sum([3, 8, 1], 9), has_pair_sum_fast([3, 8, 1], 9))   # True True
```

Это типичный обмен: память на время.

## Классы сложности

| Класс | Название | Пример | n = 10⁶ |
|---|---|---|---|
| O(1) | константа | доступ по индексу, `dict` lookup | мгновенно |
| O(log n) | логарифм | бинарный поиск, операции кучи | ~20 шагов |
| O(n) | линейная | проход по массиву | ок |
| O(n log n) | линейно-логарифмическая | сортировка | ок |
| O(n²) | квадратичная | вложенные циклы, пузырёк | 10¹² — слишком долго |
| O(2ⁿ) | экспоненциальная | все подмножества | только n до ~25 |
| O(n!) | факториальная | все перестановки | только n до ~10 |

Полезная прикидка: Python выполняет порядка 10⁷ простых операций в секунду. По ограничению на `n` в задаче можно угадать ожидаемую сложность: `n <= 20` — перебор 2ⁿ, `n <= 10⁴` — O(n²), `n <= 10⁶` — O(n log n) или O(n).

## Амортизированная сложность

Амортизированная оценка — средняя стоимость операции в **худшей последовательности** операций (не путать со средним случаем по случайным входам). Классический пример — `list.append`: когда массив заполнен, он перевыделяется с запасом (примерно в 1.125 раза в CPython) и копируется за O(n), но такие копирования редки, и суммарно n добавлений стоят O(n). Значит одна операция — O(1) амортизированно.

```python
import sys
lst, sizes = [], set()
for i in range(20):
    lst.append(i)
    sizes.add(sys.getsizeof(lst))
print(len(sizes) < 20)     # True — память растёт скачками, а не на каждом append
```

Другие примеры: вставка в хеш-таблицу с рехешированием, очередь на двух стеках, union-find со сжатием путей.

## Сложность по памяти и стек рекурсии

Память считают как **дополнительную**: сам вход обычно не учитывается. Скрытые расходы:

- срезы `arr[1:]` и конкатенация строк создают копии — O(n) памяти и времени;
- рекурсия занимает O(глубина) памяти на стеке вызовов;
- хеш-множества, мемоизация, очереди BFS.

```python
def sum_rec(arr, i=0):       # O(n) время, O(n) память на стеке
    return 0 if i == len(arr) else arr[i] + sum_rec(arr, i + 1)

def sum_bad(arr):            # O(n²) время и память из-за срезов!
    return 0 if not arr else arr[0] + sum_bad(arr[1:])

print(sum_rec(list(range(100))), sum_bad(list(range(100))))   # 4950 4950
import sys
print(sys.getrecursionlimit())   # 1000 — глубокая рекурсия упадёт с RecursionError
```

Для рекурсии полезна **мастер-теорема**: `T(n) = a*T(n/b) + O(n^d)`. Бинарный поиск `T(n) = T(n/2) + O(1)` → O(log n); сортировка слиянием `T(n) = 2T(n/2) + O(n)` → O(n log n). Наивный Фибоначчи `T(n) = T(n-1) + T(n-2)` → O(2ⁿ).

## Нижняя граница сортировки сравнением

Любая сортировка, которая только **сравнивает** элементы, в худшем случае требует Ω(n log n) сравнений. Доказательство через дерево решений: существует n! перестановок, каждое сравнение делит варианты максимум пополам, значит высота дерева не меньше `log2(n!)`, а это Θ(n log n) по формуле Стирлинга.

Обойти границу можно, только если не сравнивать: сортировка подсчётом и поразрядная работают за O(n + k), используя то, что ключи — небольшие целые числа.

> На собеседовании любят спросить: «Можно ли отсортировать быстрее n log n?» Правильный ответ: сравнениями — нет; при ограниченном диапазоне целых ключей — да, counting или radix sort.

## Частые вопросы на собеседовании

- Чем O отличается от Θ? → O — верхняя граница, Θ — точная (верхняя и нижняя одновременно).
- Сложность `list.append`? → O(1) амортизированно, O(n) в худшем единичном случае.
- Сколько памяти занимает рекурсия глубины n? → O(n) на стеке вызовов.
- Почему O(n + m) нельзя записать как O(n)? → входы независимы, любой может доминировать.
- Сложность двух последовательных циклов по n? → O(n), а вложенных — O(n²).
- Почему сортировка сравнением не быстрее n log n? → дерево решений с n! листьями имеет высоту log(n!) = Θ(n log n).

## Шпаргалка

- Отбрасываем константы и младшие слагаемые.
- Последовательно — сумма, вложенно — произведение.
- 1 < log n < n < n log n < n² < 2ⁿ < n!
- Амортизированная = средняя по худшей последовательности операций.
- Учитывайте скрытые копии (срезы, строки) и стек рекурсии.
- Мастер-теорема: делим пополам + линейная работа → n log n.
- Сортировка сравнением — Ω(n log n); подсчётом — O(n + k).
