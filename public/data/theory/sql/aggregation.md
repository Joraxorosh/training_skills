Агрегатные функции сворачивают множество строк в одно значение: сумму, количество, среднее. Вместе с `GROUP BY` и `HAVING` это самый частый инструмент аналитики. Вопросы на собеседовании проверяют поведение `COUNT` с `NULL`, агрегацию пустого набора, разницу `WHERE` и `HAVING` и правило «что можно писать в SELECT при группировке».

## Агрегатные функции и NULL

Основные функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`. Все они, кроме `COUNT(*)`, **игнорируют NULL**.

| v |
|---|
| 10 |
| NULL |
| 20 |
| 20 |

| Выражение | Результат |
|---|---|
| `COUNT(*)` | 4 — считает строки |
| `COUNT(v)` | 3 — непустые значения |
| `COUNT(DISTINCT v)` | 2 |
| `SUM(v)` | 50 |
| `AVG(v)` | 16.67 — делится на 3, а не на 4 |

Если нужно считать `NULL` как ноль, пишите `AVG(COALESCE(v, 0))`.

## Агрегация пустого набора

Без `GROUP BY` агрегатный запрос **всегда возвращает ровно одну строку**, даже если таблица пуста или `WHERE` ничего не отобрал:

```sql
SELECT COUNT(*), SUM(amount), MAX(amount)
FROM sales WHERE region = 'West';  -- такого региона нет
```

| count | sum | max |
|---|---|---|
| 0 | NULL | NULL |

`COUNT` возвращает 0, а `SUM`, `AVG`, `MIN`, `MAX` — `NULL`. Чтобы получить 0, используйте `COALESCE(SUM(amount), 0)`.

С `GROUP BY` на пустом наборе результат — **0 строк**: нет ни одной группы.

## GROUP BY

`GROUP BY` разбивает строки на группы с одинаковыми значениями ключа; `NULL` образуют одну отдельную группу. Правило: в `SELECT` можно писать только столбцы из `GROUP BY` и агрегаты.

```sql
-- ошибка в PostgreSQL: column "emp.name" must appear in the GROUP BY clause
SELECT dept, name, COUNT(*) FROM emp GROUP BY dept;
```

Исключение: если группируете по первичному ключу таблицы, PostgreSQL разрешает выводить остальные её столбцы (функциональная зависимость). MySQL со старым режимом без `ONLY_FULL_GROUP_BY` позволял любые столбцы и возвращал произвольное значение — это источник багов.

В PostgreSQL в `GROUP BY` можно ссылаться на псевдоним или номер столбца: `GROUP BY 1`.

## WHERE против HAVING

- `WHERE` фильтрует **строки до группировки**, агрегаты в нём запрещены.
- `HAVING` фильтрует **группы после агрегации**, может использовать агрегаты.

```sql
SELECT dept, AVG(salary) AS avg_sal
FROM emp
WHERE hired_at >= '2020-01-01'   -- отбор строк
GROUP BY dept
HAVING COUNT(*) >= 3;            -- отбор групп
```

Агрегатные функции допустимы в `SELECT`, `HAVING` и `ORDER BY`, но не в `WHERE`, `GROUP BY` и `ON`. Условия, не зависящие от агрегатов, лучше писать в `WHERE` — так меньше строк попадает в группировку.

## Условная агрегация

Один проход по таблице — несколько метрик:

```sql
SELECT
  region,
  COUNT(*) FILTER (WHERE status = 'paid')            AS paid,
  SUM(CASE WHEN status = 'refund' THEN amount ELSE 0 END) AS refunds
FROM sales
GROUP BY region;
```

`FILTER` — синтаксис PostgreSQL и стандарта; `CASE` внутри агрегата работает везде, включая MySQL. Обратите внимание: `COUNT(CASE WHEN ... THEN 1 END)` считает правильно (без `ELSE` получится NULL), а `COUNT(CASE WHEN ... THEN 1 ELSE 0 END)` посчитает все строки.

Полезные агрегаты PostgreSQL: `string_agg(name, ', ' ORDER BY name)`, `array_agg(x)`, `bool_and`, `bool_or`. Целочисленное деление: `SUM(int) / COUNT(*)` в PostgreSQL даст целое — приводите к `numeric`.

## GROUPING SETS, ROLLUP, CUBE

Позволяют посчитать несколько уровней группировки в одном запросе:

```sql
SELECT region, product, SUM(amount)
FROM sales
GROUP BY ROLLUP (region, product);
```

- `ROLLUP (a, b)` = `GROUPING SETS ((a, b), (a), ())` — промежуточные итоги и общий итог.
- `CUBE (a, b)` = все комбинации: `(a, b), (a), (b), ()`.
- В строках итогов «свёрнутые» столбцы равны `NULL`; отличить их от настоящего NULL помогает функция `GROUPING(col)` — она возвращает 1 для свёрнутого столбца.

## Частые вопросы на собеседовании

- Чем `COUNT(*)` отличается от `COUNT(col)`? → Первый считает строки, второй — непустые значения.
- Что вернёт `SUM` по пустому набору? → NULL; `COUNT` вернёт 0.
- Сколько строк вернёт агрегатный запрос без GROUP BY на пустой таблице? → Одну.
- Чем HAVING отличается от WHERE? → HAVING фильтрует группы после агрегации и может содержать агрегаты.
- Как учитывается NULL в `AVG`? → Игнорируется, знаменатель уменьшается.
- Что делает ROLLUP? → Добавляет промежуточные и общий итоги.

## Шпаргалка

| Ситуация | Результат |
|---|---|
| Агрегаты и NULL | игнорируют, кроме `COUNT(*)` |
| Пустой набор без GROUP BY | 1 строка: COUNT=0, остальные NULL |
| Пустой набор с GROUP BY | 0 строк |
| NULL в GROUP BY | одна группа |
| Агрегат в WHERE | ошибка |
| Условная агрегация | `FILTER (WHERE ...)` или `CASE` |
| Итоги | ROLLUP, CUBE, GROUPING SETS |
