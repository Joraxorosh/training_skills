DDL (Data Definition Language) — команды, которые описывают структуру базы: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. Вместе с ограничениями целостности и нормализацией это фундамент проектирования схемы. На собеседовании проверяют разницу между ключами, поведение внешних ключей при удалении, работу `UNIQUE` с `NULL` и умение назвать нарушенную нормальную форму.

## Создание и изменение таблиц

```sql
CREATE TABLE users (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email      text NOT NULL UNIQUE,
  age        int CHECK (age >= 0),
  status     text NOT NULL DEFAULT 'active',
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE users ADD COLUMN phone text;
ALTER TABLE users ALTER COLUMN phone SET NOT NULL;  -- ошибка, если есть NULL
ALTER TABLE users DROP COLUMN phone;
DROP TABLE IF EXISTS users CASCADE;
```

- `DROP TABLE` удаляет таблицу целиком: данные, структуру, индексы, ограничения.
- `TRUNCATE` удаляет все строки, сохраняя структуру.
- `DELETE` удаляет строки по условию (это DML).

В PostgreSQL DDL **транзакционный**: `CREATE TABLE` или `ALTER` внутри `BEGIN ... ROLLBACK` откатится. В MySQL большинство DDL выполняют неявный COMMIT.

`ADD COLUMN ... NOT NULL` без `DEFAULT` на непустой таблице упадёт. С `DEFAULT` (константой) в PostgreSQL 11+ добавление выполняется мгновенно, без перезаписи таблицы.

Автоинкремент: `serial` (старый способ, создаёт последовательность) или стандартный `GENERATED ... AS IDENTITY`. `ALWAYS` запрещает явно вставлять значение без `OVERRIDING SYSTEM VALUE`, `BY DEFAULT` — разрешает. Значения последовательности не откатываются при ROLLBACK, поэтому в id бывают дыры.

## Ограничения целостности

| Ограничение | Смысл | Создаёт индекс |
|---|---|---|
| `PRIMARY KEY` | уникально и NOT NULL, одно на таблицу | да |
| `UNIQUE` | уникально, NULL допускаются | да |
| `FOREIGN KEY` | значение есть в родительской таблице | нет |
| `CHECK` | условие не равно FALSE | нет |
| `NOT NULL` | значение обязательно | нет |
| `EXCLUDE` | обобщение UNIQUE (например, непересечение интервалов) | да |

Отличия PRIMARY KEY от UNIQUE: первичный ключ один на таблицу и не допускает `NULL`; уникальных ограничений может быть сколько угодно.

`UNIQUE` и `NULL`: поскольку `NULL` не равен `NULL`, по умолчанию можно вставить **сколько угодно строк с NULL** в уникальный столбец. В PostgreSQL 15+ это меняется опцией `UNIQUE NULLS NOT DISTINCT`.

`CHECK` с `NULL`: условие `age >= 0` для `NULL` даёт unknown, и строка **проходит**.

Индекс на столбцы внешнего ключа PostgreSQL сам не создаёт — его стоит добавить вручную, иначе удаление из родительской таблицы и соединения будут медленными.

## Внешние ключи и каскады

```sql
CREATE TABLE orders (
  id          bigint PRIMARY KEY,
  customer_id bigint REFERENCES customers(id) ON DELETE CASCADE
);
```

| Действие | При удалении родителя |
|---|---|
| `NO ACTION` (по умолчанию) | ошибка, если есть дочерние строки (проверка в конце оператора) |
| `RESTRICT` | ошибка сразу, без возможности отложить |
| `CASCADE` | дочерние строки удаляются |
| `SET NULL` | FK в дочерних становится NULL |
| `SET DEFAULT` | FK становится значением по умолчанию |

Аналогично работает `ON UPDATE`. Ограничение можно объявить `DEFERRABLE INITIALLY DEFERRED` — тогда проверка выполняется при `COMMIT`, а не после каждой команды. Строка с `NULL` во внешнем ключе проверку проходит.

## Ключи: естественные и суррогатные

- **Естественный ключ** — значение из предметной области: email, ИНН, номер паспорта.
- **Суррогатный ключ** — искусственный идентификатор без смысла: автоинкремент `id`, UUID.
- **Потенциальный (candidate) ключ** — любой минимальный набор уникальных столбцов; один из них выбирают первичным.
- **Составной ключ** — из нескольких столбцов, например `(order_id, product_id)`.

Суррогатные ключи не меняются при изменении бизнес-данных, поэтому их обычно выбирают первичными, а естественные закрепляют `UNIQUE`.

## Нормализация

1. **1НФ** — значения атомарны, нет повторяющихся групп. Нарушение: столбец `phones = '111, 222'` или столбцы `phone1, phone2, phone3`.
2. **2НФ** — 1НФ, и неключевые атрибуты зависят от **всего** составного ключа. Нарушение: в `order_items(order_id, product_id, product_name)` имя товара зависит только от `product_id`.
3. **3НФ** — 2НФ, и нет транзитивных зависимостей: неключевой атрибут не зависит от другого неключевого. Нарушение: `employees(id, dept_id, dept_name)` — `dept_name` зависит от `dept_id`.
4. **НФБК** — каждый детерминант является потенциальным ключом.

Если у таблицы простой (не составной) первичный ключ и она в 1НФ, то 2НФ выполняется автоматически.

**Денормализация** — сознательное дублирование данных ради скорости чтения (счётчики, кэш-столбцы, витрины). Цена — усложнение записи и риск рассогласования.

## Представления и схемы

```sql
CREATE VIEW active_users AS SELECT * FROM users WHERE status = 'active';

CREATE MATERIALIZED VIEW sales_daily AS
SELECT date_trunc('day', created_at) AS d, SUM(amount) FROM sales GROUP BY 1;
REFRESH MATERIALIZED VIEW CONCURRENTLY sales_daily;  -- нужен UNIQUE индекс
```

Обычное представление — сохранённый запрос, выполняется при каждом обращении. Материализованное хранит результат физически и обновляется только командой `REFRESH`; на него можно строить индексы.

Схема (schema) — пространство имён внутри базы: `reports.sales`. По умолчанию объекты создаются в `public`, а поиск идёт по `search_path`.

## Частые вопросы на собеседовании

- Чем PRIMARY KEY отличается от UNIQUE? → PK один, NOT NULL; UNIQUE может быть много и допускает NULL.
- Можно ли вставить два NULL в UNIQUE-столбец? → Да (если не указано NULLS NOT DISTINCT).
- Что происходит по умолчанию при удалении родителя с детьми? → Ошибка (NO ACTION).
- Какие ограничения создают индекс? → PRIMARY KEY, UNIQUE, EXCLUDE.
- Чем DROP отличается от TRUNCATE и DELETE? → DROP удаляет таблицу, TRUNCATE все строки быстро, DELETE строки по условию.
- Что нарушает таблица `emp(id, dept_id, dept_name)`? → 3НФ (транзитивная зависимость).

## Шпаргалка

| Тема | Правило |
|---|---|
| PK | уникально + NOT NULL, индекс |
| UNIQUE и NULL | несколько NULL разрешены |
| CHECK и NULL | проходит |
| FK по умолчанию | NO ACTION — ошибка |
| Индекс под FK | создавать вручную |
| 1НФ / 2НФ / 3НФ | атомарность / весь ключ / нет транзитивности |
| DDL в PG | транзакционный |
| MATERIALIZED VIEW | хранит данные, обновляется REFRESH |
