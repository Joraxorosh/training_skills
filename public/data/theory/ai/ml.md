Машинное обучение — это построение моделей, которые находят закономерности в данных, а не следуют вручную написанным правилам. На собеседовании проверяют не столько формулы, сколько здравый смысл: как правильно разбить данные, как распознать переобучение, какую метрику выбрать при дисбалансе классов и где прячется утечка данных.

## Типы задач

- **Обучение с учителем (supervised)** — есть признаки `X` и целевая переменная `y`. Если `y` — категория, это **классификация** (спам/не спам). Если число — **регрессия** (цена квартиры).
- **Обучение без учителя (unsupervised)** — меток нет, ищем структуру: кластеризация (k-means, DBSCAN), понижение размерности (PCA), поиск аномалий.
- **Обучение с подкреплением (RL)** — агент действует в среде и получает награду; так учат игровых ботов и роботов, а также дообучают LLM по предпочтениям.

## Разбиение данных и переобучение

Данные делят на **train** (обучение), **validation** (подбор гиперпараметров и выбор модели) и **test** (одна финальная оценка). Если многократно выбирать модель по валидации, оценка на ней становится оптимистичной — поэтому тест трогают в самом конце.

| Ситуация | Ошибка train | Ошибка val | Что делать |
|---|---|---|---|
| Недообучение (high bias) | высокая | высокая | сложнее модель, больше признаков, меньше регуляризации |
| Переобучение (high variance) | низкая | высокая | регуляризация, больше данных, проще модель, early stopping |
| Норма | низкая | близкая к train | — |

**Bias-variance trade-off**: простая модель систематически ошибается (смещение), сложная чувствительна к шуму конкретной выборки (дисперсия). Цель — минимум суммарной ошибки.

**Регуляризация** штрафует большие веса. **L1** (Lasso, штраф `|w|`) зануляет часть весов и отбирает признаки. **L2** (Ridge, штраф `w²`) равномерно уменьшает веса. ElasticNet комбинирует оба.

**Кросс-валидация** (k-fold) усредняет оценку по k разбиениям и даёт более стабильный результат на небольших данных. Для временных рядов используют `TimeSeriesSplit`: валидация всегда после обучения.

## Утечка данных

**Data leakage** — информация, которая не будет доступна в момент предсказания, но попала в обучение. Модель выглядит отлично офлайн и проваливается в проде.

- Признаки «из будущего»: число возвратов за следующий месяц в модели оттока.
- Предобработка на всём датасете до разбиения: `StandardScaler`, target encoding, отбор признаков.
- Дубликаты одного пользователя по обе стороны разбиения — нужен group split.
- Случайное перемешивание временного ряда.

```python
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

model = make_pipeline(StandardScaler(), LogisticRegression(class_weight="balanced"))
scores = cross_val_score(model, X_train, y_train, cv=5, scoring="average_precision")
```

`Pipeline` гарантирует, что scaler обучается только на обучающей части каждого фолда.

## Метрики

Из матрицы ошибок (TP, FP, FN, TN):

- `accuracy = (TP + TN) / всего` — бесполезна при дисбалансе.
- `precision = TP / (TP + FP)` — какая доля сработок верна.
- `recall = TP / (TP + FN)` — какую долю положительных нашли.
- `F1 = 2·P·R / (P + R)` — гармоническое среднее, тянется к меньшему.
- **ROC-AUC** — качество ранжирования, не зависит от порога; при сильном дисбалансе выглядит оптимистично из-за огромного TN.
- **PR-AUC** — площадь под кривой precision-recall, честнее для редкого класса.
- Регрессия: **MAE** (средняя абсолютная ошибка, устойчива к выбросам), **RMSE** (сильнее штрафует большие ошибки), R².

> Пример: TP = 40, FP = 10, FN = 20, TN = 930. Accuracy = 0.97, но precision = 0.8, recall ≈ 0.67 — модель пропускает треть положительных.

**Дисбаланс классов**: если мошенничества 1%, константный ответ «не мошенничество» даёт 99% accuracy. Помогают правильные метрики, `class_weight`, over/undersampling (SMOTE), подбор порога. Снижение порога повышает recall и обычно снижает precision.

## Основные модели

| Модель | Идея | Особенности |
|---|---|---|
| Линейная регрессия | `y = w·x + b`, минимизация MSE | интерпретируема, нужна предобработка |
| Логистическая регрессия | линейная модель для log-odds, сигмоида, log-loss | baseline для классификации, даёт вероятности |
| Дерево решений | последовательные пороговые разбиения | не нужно масштабирование, легко переобучается |
| Random Forest | бэггинг независимых деревьев + случайные признаки | снижает variance, устойчив, мало настроек |
| Градиентный бустинг | деревья строятся последовательно по градиенту ошибки | часто лучший на таблицах, чувствителен к гиперпараметрам |
| k-means | точки к ближайшему центроиду | нужно задать k, кластеры выпуклые, чувствителен к масштабу |

## Признаки и масштабирование

**Feature engineering** часто даёт больше, чем смена модели: агрегаты по пользователю, признаки из даты (день недели, праздник), отношения величин, one-hot или target encoding категорий. Масштабирование (`StandardScaler`, `MinMaxScaler`) критично для алгоритмов на расстояниях и градиентах — k-NN, k-means, SVM, линейные модели с регуляризацией, нейросети. Деревья к масштабу инвариантны.

## Частые вопросы на собеседовании

- Accuracy 99% на несбалансированных данных — хорошо? → Нет, сравните с константным классификатором и смотрите precision/recall/PR-AUC.
- Как отличить переобучение от недообучения? → Сравнить ошибки train и validation.
- L1 vs L2? → L1 даёт разреженность и отбор признаков, L2 сглаживает веса.
- Random Forest vs бустинг? → Параллельные независимые деревья против последовательного исправления ошибок.
- Где может быть утечка? → Признаки из будущего, preprocessing до split, дубликаты, перемешанные временные ряды.
- Зачем test, если есть validation? → Validation «использована» для выбора модели, test даёт честную финальную оценку.

## Шпаргалка

- train / val / test; k-fold; `TimeSeriesSplit` для времени; group split для пользователей
- high bias → усложнить; high variance → регуляризация, данные, упрощение
- L1 → нули в весах; L2 → маленькие веса
- `precision = TP/(TP+FP)`, `recall = TP/(TP+FN)`, `F1 = 2PR/(P+R)`
- дисбаланс → PR-AUC, `class_weight`, порог
- RF снижает variance, бустинг — bias
- scaler и энкодеры обучать только на train, через `Pipeline`
